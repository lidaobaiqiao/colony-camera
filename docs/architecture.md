# 项目架构

## 玩法目标

玩家在第一人称中搭建自己的道路、建筑和生产设施，保存为可复用预设，再切换 SLG 视角规划殖民地，由殖民地执行施工。系统最终应理解结构的入口、连接和实际功能，让玩家的设计影响经营。NPC 任务执行为这个循环服务。

当前实现第一人称与 SLG 视角切换、镜头运动、方块选择、自定义预设、本地投影、打印核心、服务端建造/挖掘/清扫、工作站合成与逐级科技，以及有限容量存储网络。

## 当前边界

采用单个 Gradle 工程，按功能分包；保留 `dev.colony.camera` 根包、`ColonyCamera` 入口和 `colonycamera` 模组 ID。

| 位置 | 职责 | 边界 |
| --- | --- | --- |
| `ColonyCamera` | Forge 模组入口与身份 | 不加载客户端类，不承载镜头逻辑 |
| `client.camera` | `CameraState` 负责状态与计算，`StrategyCameraController` 负责进入、退出和摄像机应用 | 不管理按键注册或界面绘制 |
| `client.input` | `CameraKeyMappings` 注册按键，`CameraClientEvents` 适配客户端事件与输入 | 将输入交给镜头控制，不重复保存镜头状态 |
| `client.screen` | `StrategyScreen` 路由输入，`StrategyHud` 绘制，纯 Java `StrategyHudLayout` 共享布局与命中 | 不直接进行世界修改 |
| `client.selection` | 摄像机鼠标射线、单方块选择、相似扩展、固定面立体扫描及轮廓缓存 | 仅查询已加载世界和保存本地选择，不执行实体交互或世界修改 |
| `src/main/resources` | 模组元数据、语言文件、访问转换器 | 翻译键使用 `colonycamera` 命名空间 |

`CameraState` 保持纯 Java：仅负责焦点、距离、角度锁定、运动和缩放约束，不依赖 Minecraft、Forge 或界面。`CameraFrameClock` 将单调时钟转换为受限的帧时间。控制器负责把游戏坐标和输入转成状态操作，再将结果应用到 Minecraft 摄像机。

Client tick 只负责进入、退出与失焦清理；键盘平移和升降在 RenderTick START 按帧时间推进，避免仅每秒 20 次更新且无插值的台阶运动。鼠标输入保持事件驱动。帧间移动时间最多 50 ms，进入/退出/失焦时重置时钟，避免恢复窗口后补跑长时间位移。

状态归控制器管理，界面只是客户端交互入口。进入、退出、界面替换、离开世界需要走同一套收尾逻辑，恢复视角和临时修改的选项、释放按键；重复退出应安全。不要让每个事件处理器分别维护一份 `active` 状态。

战略 HUD 分为标题、选区信息、底部工具、阶段提示和右上角镜头操作。布局仅在初始化/缩放时计算；实际绘制与鼠标命中使用同一组 GUI 坐标矩形，独立测试 320×180 起的常见尺寸和短暂极小窗口。选择控制器提供数量、单选名称/坐标、高度、工作状态和通知，不让界面解析拼接后的说明文字。帮助行在初始化时缓存，工具提示使用当前绑定，过长信息截断后可悬停查看。

UI 比世界鼠标动作和重绑定的鼠标快捷键优先；面板阻止新选择和镜头拖动，世界框选在 UI 上松开不提交。Forge 事件桥接将共享命中结果传给选择渲染，禁用面板背后的悬停射线及拖动终点更新，已提交选择和分帧作业继续绘制/推进。帮助作为当前 Screen 内的模态层，控制器输入门禁暂停镜头，全部鼠标位置属于界面，关闭点击不传给世界。F6/Esc 仍退出整个战略视角。

高度阶段进入/离开 UI 重设 Y 基准，UI 内释放横向约束；回到场景重新固定当前 X，避免穿过按钮时改变层数。延迟 GLFW 操作再次检查 UI 命中，帮助/取消后的旧请求不能锁回光标。原版底部快捷栏、角色数值栏和药水图标仅在战略会话中通过 overlay 事件隐藏，退出不需要修改或恢复游戏设置。界面选择见 [决策 0007](decisions/0007-strategy-hud.md)。

选择在 `RenderLevelStageEvent.AFTER_BLOCK_ENTITIES` 使用真实投影与视图矩阵生成摄像机射线，按 OUTLINE 检测种子并描边。默认单选在鼠标按下时排队，只提交实际命中的一个坐标；相似模式才进行邻接扩展。点击操作捕获射线视图、工具模式、追加开关和单次上限，不再提供普通表面框选。立体模式仍固定按下时的实际命中面拖底面，松开选高。

`FaceSelection` 保持纯 Java，保存起点格、命中面方向及实际面的坐标。立体拖动始终使用固定平面求交，不跟随其他方块切换参考面；矩形包含两端格，台阶等半格面保持实际高度。六个轴向面共用几何，平行、后向、非有限或超距离的交点不能更新或提交。

立体选择复用同一底面：V 模式左键松开后进入高度阶段，固定鼠标横向位置，上下移动鼠标调整沿命中面法线的有符号层数，再左键确认。正层数向外、负层数向内，绝对值包含底面一层，零层不合法；墙面沿 X/Z 扩展厚度，上下表面沿 Y 扩展高度。高度阶段固定底面，绿色/红色轴线指示向外/向内，黄色标记显示延伸位置，滚轮始终缩放镜头。

纯 Java `HeightSelection` 累积鼠标竖直位移，并按当前一格轴线的屏幕长度换算、对称吸附到整数层。控制器以当前真实投影视图矩阵投影底面端点与沿法线一格的点，求像素长度；最低每格 4 像素避免接近正视轴线时过敏，投影无效时回退每格 24 像素。只在鼠标实际移动时积分，所以新的缩放/角度/相机位置本身不会改层数。中键/右键镜头拖动期间只重设鼠标基准；释放后从当前位置继续，保留层数和亚格位移。

`StrategyScreen.mouseMoved` 仅在高度阶段且窗口活跃、没有镜头拖动时更新高度及请求限制鼠标 X。原版 `MouseHandler` 在该回调之后才更新自身坐标，因此使用始终入队的 `Minecraft.tell` 延后光标重定位，合并同一批输入的请求，执行时读取已更新的最新 Y。不能使用可能立即执行的 `execute`，也不能在原鼠标回调内触发 GLFW 嵌套回调，让外层处理覆盖新光标坐标。队列操作执行前重新核验当前界面、窗口焦点及选择/拖动阶段；约束不改变 GLFW 抓取模式，确认、取消或失焦后不再重定位光标。

相似模式使用纯 Java `SimilarSelectionJob`，以种子为起点广度优先遍历全部 26 邻居；连接判断为同一 Block 类型，不按 BlockState 拆分。种子计入单次上限，默认 64，可设置 1–8192；达到上限终止扩展。每步至多调用一次 Source.sample，坐标加法使用 long 检查整数溢出。

世界适配只查询已加载区块，加载状态用 `level.getChunkSource().hasChunk` 核验；不能用该版本恒为 true 的 ClientLevel.hasChunk。无效高度/边界视为非匹配，缺失区块使整次操作失败。扫描后分帧复查采样匹配，完成前复查已查询区块；成员匹配变化或卸载时保留原选区，不提交部分结果。

`SelectionState` 管理成员、追加开关及 SINGLE/SIMILAR/VOLUME 模式，总量最多 8192；替换或并集在限额检查后原子提交。V 往返保留上次非立体工具，工具切换取消未完成操作且保留已提交集合；会话重置恢复单选。选择工具同时释放未放置投影草稿，不改变已受理服务端工程。相似模式只限制本次新增片段，立体闭区间体积最多 8192 格、包含空气，最终保留所有非空气方块。立体范围校验世界高度、边界和区块，完成前复查整体加载状态。

作业在主线程分帧推进：相似扫描及验证每帧最多 2048 步、约 2 ms，立体每帧最多 256 格、约 2 ms。旧选择保留至作业成功；相似作业不显示未完成片段，立体继续显示固定底面和长方体预览。两种操作都不使用屏幕像素采样。

`SelectionBoxes` 贪心合并完整方块，结果准确覆盖集合且不填补未选洞；异形方块保留形状描边。形状缓存每帧最多构建 256 项、约 1 ms，失效检查每帧最多 64 项。时间预算是软限制，单次世界查询无法中断，不代表整体帧时间或 FPS 保证。

选择操作串行排队，捕获开始时的追加模式。镜头拖动取消底面，但选高期间可移动镜头；失焦/窗口缩放取消未完成作业并保留已提交集合，退出重置全部。空气及卸载成员分帧移除。独立工具及默认单选见 [决策 0017](decisions/0017-independent-single-selection.md)，相似规则与设置见 [0013](decisions/0013-similar-selection.md)，高度输入见 [0006](decisions/0006-mouse-height.md)，固定面见 [0004](decisions/0004-face-selection.md)；[0005](decisions/0005-surface-selection.md) 仅记录已移除的历史表面方案。

SLG 保持 Minecraft 的第一人称类型，并通过镜头事件调整视角，利用原版的本地玩家隐藏规则；客户端事件同时屏蔽手持物品、原位视野遮罩与旧玩家高亮，玩家渲染前事件作为隐藏兜底。这些事件只在 SLG 活跃时生效，不修改实体可见性或服务器状态。

相机选择结果不写入 `Minecraft.hitResult`，防止原版交互把远处的本地选择当成可挖放目标。未来规划可复用选择信息；涉及世界修改时仍须通过服务端校验。具体渲染与权限取舍见 [决策 0002](decisions/0002-camera-selection.md)。

所有 `net.minecraft.client` 引用限制在 `client` 包，事件订阅显式限定 `Dist.CLIENT`。纯 Java 代码放在客户端功能包中不代表可以随意从服务端加载客户端适配类。

场景右键区分单击与拖动：4 个物理像素以下松开清空选区，达到阈值开始镜头平移，发生过拖动就不能再按单击清空。仅场景中开始和结束、无投影草稿的右键手势可清空；UI、失焦与退出清理手势。Delete/工具栏继续保留。

## 设计、规划与施工边界

1.6.0 的 BuildPanel/BuildCatalogFilter/BuildPanelLayout 提供方块目录和共享点击几何，BuildingClient 发出受限意图、等待确认。BlockBuilding 从注册物品生成默认小预设，BuildCatalogService 分步查询真实可达成品及站点生产可行性，BuildNetwork 验证后创建工程及关联合成任务；施工仍通过 ConstructionManager 执行。投影以工程快照恢复，父子任务共享优先度、序号和预约，详见 [决策 0016](decisions/0016-building-palette-and-supply.md)。

1.6.1 的建造目录使用左侧窄栏、图标颜色和悬停详情，放置时使用单行工具条。只有实际绘制的面板/状态区拦截世界输入；隐藏的空选区与闲置提示不留透明障碍。搜索框焦点决定键盘输入归属，面板外鼠标平移/旋转/缩放继续有效。目录工程的可替换判断在鼠标锚点、预览和服务端执行中一致，仅允许空气或无液体可替换状态；普通预设施工仍使用原有冲突规则。

1.5.1 将工人可达性探查与执行导航分开：WorkerEntity 的规划导航器只创建候选路径，GroundResources.follow 才为实际导航器创建并提交路线。探查不能改变执行目标、活动路径或卡住计时；规划浮水设置同步实际导航。清扫在没有地面物品时仍等待同属殖民地工人手中材料入仓，不能由空手工人提前宣布完成。两项错误与修复证据见 [决策 0014](decisions/0014-navigation-probes-and-sweeping-completion.md)。

1.5.2 使用 WorkerWalkNodeEvaluator 和脚底层导航位置处理浅水路线，Forge 游泳属性增强水中水平推进力；水中上浮与爬出台阶分开处理。挖掘站位允许有坚实地面、头部无液体的浅水，抵达后停下导航并在工作期间抵抗水流；打印继续使用干地。旧工人读档更新游泳基值，保留归属与真实库存。深水潜泳施工不在此版本范围，详见 [决策 0015](decisions/0015-worker-water-movement.md)。

| 功能 | 负责什么 | 执行端 |
| --- | --- | --- |
| `preset` | 结构捕获、锚点和接口、旋转、资源清单、版本化存储 | 编辑与预览在客户端，持久化和使用校验按实际部署需求决定 |
| `planning` | 区域选择、摆放预览、道路重复和连接、规划数据 | 客户端交互；服务端确认可执行的规划 |
| `construction` | 工程材料账单、施工队列、工人实际取料/施工及失败处理 | 服务端权威执行 |
| `resources` | 地面与容器资源发现、实际取用校验及纯 Java 预约账本 | 服务端；客户端只显示统计与状态 |
| `worker` | 工人归属、持料 NBT 与只查已加载区块的寻路 | 实体服务端运行；客户端独立渲染器 |
| `network` | 大小受限、方向固定的施工意图与每玩家状态快照 | 双方安装同版，主线程执行 |
| `storage` | 箱子格子/堆叠升级、有限容量持久化、网络连通与统一端口存取 | 服务端库存与拓扑；客户端菜单 |
| `work` | 版本化挖掘、清扫、合成和研究任务，共享建造调度与预约 | 服务端执行；`client.work` 管界面 |
| `crafting` / `tech` | 真实配方库存事务、研究材料与玩家科技进度 | 服务端校验、消费和保存 |

预设描述“玩家设计了什么”，规划描述“准备在哪里建”，施工描述“当前执行到哪里”。预览不能直接修改世界。创建工程才提交服务端请求并生成独立快照；之后修改本地投影不移动工地，不撤销已建方块。

预设持久化落地时必须包含独立的格式版本，并为不兼容数据提供迁移或明确拒绝。运行中的施工状态不要塞进可复用的预设文件。

## 保留的限制

当前镜头使用透视投影，进入时以 60° 俯角锁定。角度锁定仅限制中键旋转，右键平移和缩放不受影响；解锁后按 yaw/pitch 绕焦点旋转，俯角限制在 15°–85°。鼠标拖拽保留实际位移，键盘平移做斜向归一化，两者共用镜头相对坐标与水平边界计算。重新锁定保留当前角度，新的视角会话恢复默认值。

升降改变世界 Y 的焦点高度，与 zoom 距离和 pitch 俯角独立，默认空格/C，可重绑；锁定角度不限制移动。三个方向统一归一化，避免组合输入加速。HUD 使用独立几何布局，选择信息在控制器状态变化时更新，绘制按当前模式呈现。

没有切层、地形避让或远程区块加载。水平移动受角色附近的渲染范围限制；选择只访问已加载方块。角色仍在世界中，世界继续运行，本地模型隐藏不提供免伤或服务器隐身。新增视角行为分别回归，不能借用旧版验收结果。

拆包是为了明确职责。只有独立发布、依赖或测试需求确实出现时，才考虑拆为 Gradle 子工程；不要为预期功能创建没有调用方的接口和空模块。架构取舍记录在 [决策 0001](decisions/0001-project-boundaries.md)。

## 1.1.0 本地投影

`preset` 包含纯数据 `BlockPreset`、调色板 `PresetCodec` 和文件库 `PresetRepository`；`planning` 包含独立的 `ProjectionPlacement`、`ProjectionCodec` 与 `ProjectionRepository`，不依赖客户端类。`client.preset` 捕获/解析方块状态，`client.planning` 管理当前世界的投影与透明渲染；`ProjectionPanel` 是 StrategyScreen 内部 UI，`ProjectionPanelLayout` 保持纯 Java。预设不知道某个投影的位置或生命周期。

预设捕获仅保存已选非空气方块，不自动填充空气或复制方块实体/物品。投影保存完整预设快照，草稿独立于已确认集合，写盘成功后再替换原投影。资源包和世界上下文改变时清理模型缓存；确认投影不写真实世界。格式、保存作用域与渲染支持见 [决策 0008](decisions/0008-local-projections.md)。

工程调度先按玩家设置的优先度，再按单调创建序号；材料预约和运输服从同一顺序。NPC 寻路和局部执行不能自行绕过这个分配规则；未来生产任务须继承工程优先度。

施工资源按工人能否实际到达并取用判断，地面材料无需先入仓即可用于施工。仓储从可升级箱子发展为统一网络，格子数量与堆叠倍率分别计算；工人可通过可达端口取用网络库存，多个端口与已联网箱子不能重复发布同一批资源。玩法要求见 [决策 0009](decisions/0009-reachable-resources-and-storage.md)，1.3.0 实现边界见 [决策 0011](decisions/0011-printing-core-and-storage.md)。

## 1.2.0 服务端工程

`ConstructionManager` 是每服务端维度的 SavedData（schemaVersion 1），保存工程快照、归属、优先度、创建序号和完成位图。调度每秒及必要变更后按 `ProjectOrder` 重建 `ReservationLedger`，工人每 5 tick 执行；预约只锁定数量，拾取时从真实 ItemEntity 分离物品，随后保存在实际 MAINHAND，放置成功后消费。

`BuildPlan` 共享 `BlockStateResolver` 的旋转/镜像解析，生成施工单元和物品账单。门/床成对，一组一件；双层半砖两件。既有一致方块视为已完成，其他非空气冲突不替换。分组放置使用快照、支撑复查和 Forge 放置事件，拒绝或失败恢复方块并保留材料。

来源消失、移动、权限改变或路线失效时释放预约并重试。拾取前验证第二段路线；暂停/取消/卸载只丢弃瞬时任务，不擦除持料。SavedData 坏格式保留原内容、禁止施工，避免失败加载被空数据覆盖。普通可建状态和已加载地面路线为当前支持边界，见 [决策 0010](decisions/0010-ground-construction.md)。

1.6.1 起 WorkerEntity 的可选 ColonyCargoTask 标记真实主手物品的任务归属。建造/清扫拾取时标记，物品消耗、成功入仓或实际掉落后清理；瞬时导航重排不清理归属。清扫只等待本任务持料，未完成/暂停建造和其他工作任务持料受保护；取消或孤立持料仍可归仓。旧工人不含该标签时按未完成施工需求恢复，不移动物资或重新写入原存档文件。保存兼容与歧义见 [决策 0018](decisions/0018-task-owned-worker-cargo.md)。

`src/gameTest` 独立源集验证实体、世界和事件行为，模板不进入正式 JAR。它不加载客户端渲染和输入；工程 UI、实体外观以及真实多人网络验收另列。

## 1.3.0 打印与仓储

`content.ColonyContent` 在公共 MOD 总线注册五种方块、两个升级件、方块实体、菜单及创造分页；客户端只注册菜单 Screen。`PrintingCores` 维护已加载核心索引，随方块卸载与世界退出清理。打印意图由服务端检查归属、权限、冷却和站位，工程创建的范围基准包含自有核心。网络协议升为 2，双方必须同版安装。

`WarehouseInventory` 在容器内保留大数量，保存为一件物品模板加独立整数 count；升级原子检查容量与每格上限，未知或坏库存保留原标签并禁用取用。`ChestConversion` 通过物品优先交互避免箱子先打开菜单，替换前快照并清空旧箱的掉落来源；失败恢复快照，成功后才消费升级件。

`StorageNetwork` 遍历同归属、已加载、相邻面连接的节点，每 tick 缓存连通分量，变更立即失效。每分量最多 256 节点且恰好一个控制器；库存仍在仓储箱，端口只有查询和路由能力。`StorageAccess` 汇总按物品与 NBT 区分的类型，`NetworkItemHandler` 将端口提供给 Forge 自动化接口。控制器不是工人取料点。

`StorageResources` 适配普通 Forge 容器、独立仓储和网络端口，网络来源身份由维度、控制器位置和材料确定，双箱两半也共享来源身份。端口改变不会复制预约；实际提取前重解连通关系、数量、权限与工人路线。上锁原版容器拒绝，双箱先确认两半已加载再解析合并接口。失败来源短暂缓存用于公平分配寻路预算。

`StorageMenu` 的 36 格是当前页类型预览，真实物品始终在库存；显示栈按原生上限截断，真实数量以拆分的整数属性同步。鼠标、Shift 与快捷栏操作由服务端向真实库存存取，满仓转移返回空结果结束重试；拖拽和双击收集暂不支持。`client.storage.StorageScreen` 绘制分页、大数量和连通状态。闲置整理入仓、库存搜索、生产链及客户端/多人/性能验收仍待补充。

## 1.4.x 挖掘、清扫与殖民地生产

以下固定生产目录描述 1.4.x 历史实现，1.10.0 的完整工作台配方与精确清扫契约见文末。

`ColonyWorkManager` 保存附加任务并与 `ConstructionManager` 共享创建序号、工人池和 `ReservationLedger`。挖掘保存受理时的精确方块状态，`MiningService` 在服务端用真实副手工具调用生存破坏流程；`SweepService` 将有限选区内的掉落物先拾取到主手，再写入自有仓储或有效网络端口。任务暂停、取消、满仓、断连和来源变化保留实体持料或地面物品。

`CraftingService` 以工作站为中心三格收集已加载、自有且站位可触及的仓储/端口，在副本库存中预演十三种原版工具/木棍配方及十二种殖民地设施/升级件配方的扣料、产物和余料，完成时复查原库存与预约并原子提交。设施/升级件无需研究，避免研究台与仓储依赖自身科技；注册物品通过 Supplier 在配方使用时解析。分配和执行使用同一站位复查取用射线，避免重新计算时隔着工作台误判，同时保持墙体遮挡。`TechProgress` 按维度和玩家保存研究等级，坏或未知数据只读保留；科技等级独立于工人挖掘属性，分别控制工具解锁和开采门槛。`client.work` 负责 O 面板、工作站入口和服务端快照。

挖掘、清扫、合成和研究沿用建造的优先度 9 到 1、同级序号 FIFO 和实际执行前复查。自动生产前置链及工程优先度继承尚未实现。详细取舍见 [决策 0012](decisions/0012-colony-work-and-technology.md)。

## 1.8.0 挖掘调度

挖掘算法的性质与目标以 [0021](decisions/0021-mining-algorithm-baseline.md) 为准。`MiningFrontier` 维护目标周围真实世界的开放面和局部空间查询；区域外的实体墙仍是遮挡，空气只影响暴露面，不成为待挖目标。`MiningPartition` 按剩余工作量和工人速度生成空间分工偏好，工人可以接手其他区域，不构成硬边界。

`MiningPlan` 保存会话内的站位、分工偏好和受阻记录；`MiningScheduler` 在统一优先度调度内认领目标，先保持已有工作，再覆盖当前站位的多个合法目标，最后才选择下一站。规划使用独立导航器；同一路线的执行仍通过 `GroundResources.follow` 续行。真实工具领取、权限、视线、工人脚下支撑和生存破坏流程保留在 `MiningService`，几何规划本身不赋予破坏权限。

`MiningProgress` 按工程目标积累破坏进度，每个服务端 tick 至多推进一次；成功破坏或目标变化后清除。`WorkTask` 只承载瞬态分配，换位、换工人或优先任务抢占不会清零已做的工作。附加任务 SavedData 使用 schema 3 的稀疏进度条目；旧 1/2 保留原契约及完成位图并从零部分进度迁移，损坏数据原样只读保留。格式与可替换的实现选择见 [0023](decisions/0023-mining-work-and-progress.md)。

## 工人状态与生活（1.9.0）

`worker.WorkerState` / `WorkerProfile` / `WorkerAttribute` 是纯 Java 输入模型，定义十八属性与六层十六职业；BigInteger 保留无上限点数及有效工作积累，七个游戏日为基础斜率。`WorkerEffects` 分别映射物理效果，`WorkerConfig` 独立定义各属性、职业即时加成/成长及特殊指令的温和占位值。能力路由独立于效率数值，现有生产/研究/教学模块消费相应能力，其余具体职业行为留给独立模块，快照明确区分。MiningSkill 已删除，旧阈值仅留在迁移函数中。

`WorkerLiving` 在真实实体 tick 处理代谢、食物取用、住所休息与学堂学习；工人不可调度时独占其导航，调度器不能停止生活路线或改动持料。`Residences` 根据玩家建造的房间识别独立床位，设施保存认领 UUID，卸载不释放；死亡、销毁或跨维度迁移释放原房间。`WorkerOrders` 验证玩家专属特殊指令，实际伤害、视线与同殖民地沟通影响可见压力来源。`WorkerSnapshots` 只发布受限的真实状态，`client.work.WorkerPanel` 显示并提交意图。

`LoadedGroundNavigation` 允许规划木门路线，`WorkerDoorGoal` 负责原版开关动作。每次动作都检查已加载位置、殖民地归属、世界权限和 Forge 右键方块事件；权限拒绝保留门状态和住所认领，不改变实体碰撞或瞬移。

工作持料的额外数量由实体整数保存，原版主手只显示一个原生堆叠，所有提取、建造消耗、清扫入库和死亡掉落仍操作同一份真实库存。施工在实际身体离开待建方块碰撞区域后才推进，低优先工程不能改签高优先持料。合成/研究累计有效工作记在 ColonyJob 中，预约仍是临时意图，最终库存事务继续复核。

保存和迁移、房间识别边界、学习内容和数值配置见 [0026](decisions/0026-worker-state-first-implementation.md)。

1.10.1 按用户纠正使打印与住房数量独立。`ConstructionManager.printWorker` 只按核心、权限、冷却、人口性能上限、出生配置及安全站位受理，住房是可选自动分配；无房工人可参与普通工作。`Residences` 的一人一间约束仍用于居住和学习，不再充当出生门槛。

1.10.2 的 `SweepService` 复查并保留有效拾取来源、已选仓库和取用站位；`WorkPaths.beside` 提供旧站位优先的可达/视线核验，不改动规划以外的导航。没有临时目的地时，`StorageResources.colonyStores` 查询导航范围内的已加载自有仓储/端口以恢复明确交付意图，其他扫描继续按搜索属性。入仓按实际距离和视线成立后停下导航并存放，减少格子中心争抢；详见 [0028](decisions/0028-sweep-delivery-continuity.md)。

## 配方书、任务标记与顶面清扫（1.10.0）

`CraftingService` 从真实服务器注册表解析普通有序/无序工作台配方，产物不限于方块；真实输入匹配、NBT、余料、空间与既有预约共用生产事务。固定工具条目只提供按产物判断的科技要求，不再限制目录。建造前置仍筛选方块产物。`previewPage` 用库存副本预演所选批次，前一轮的产物/余料进入下一轮；不创建预约或影响执行导航。

`client.work.CraftingPanel` 接管合成页，使用原版已同步的工作台配方注册表及原生图标/输入组件；搜索、分类、材料替代和数量预览均在客户端。可见页向服务器请求状态，工作网络协议 3 增加独立 `CraftView`，常规任务快照不再广播整个配方目录。`CraftingPanelLayout` 是纯 Java 几何，发布与架构检查均涵盖它。特殊动态配方显示但不能自动生产，机台配方及递归生产链另行实现。

`ColonyJob.surfaceSweep` 区分新精确顶面列表与旧范围端点，SavedData schema 5 迁移旧 1–4 而不改变已有清扫含义。`SweepService` 的包围盒仅作粗查，成员与拾取前复查仍使用精确集合、脚下碰撞部件高度和垂直遮挡；不选缝隙或其他层。拾取站位须物理可站、可见且可达，实际作业继续依赖原版导航及真实仓储。

`WorkTargetMarks` 从本玩家未完成/未取消任务生成有限页面，暂停任务仍保留；黄色挖掘、蓝色清扫与旧范围分别同步。`WorkTargetRenderer` 在客户端收到同请求完整页面后更新，退出世界/换维度清空，SLG 中只读取已加载方块的形状绘制。任务标记生命周期与本地鼠标选择独立，清空选区不取消工作。实现选择和兼容见 [0027](decisions/0027-recipe-book-and-surface-sweep.md)。

## 1.11.0 类型与个体配置

`TypeSelection` 是纯模型，`BlockSelectionController` 在立体扫描确认时捕获快照并在完成时复核；`RegistryPicker` 提供共用的原生搜索、多选和真实物品栏单选弹窗。`SweepPanel` / `ResidencePanel` 嵌入 `WorkPanel`，所有键鼠先到模态子页，第一人称与 SLG 共用服务端入口。菜单保持双端底栏，不增加常驻按钮。

`ItemSweepService` 处理有限 UUID 批次的分步物理可达检查，`SweepService` 继续执行真实拾取/入仓。`ColonyJob.itemTypes/sweepDrops` 与顶面/旧范围分开，任务 SavedData schema 6 从 1–5 迁移，类型任务不画成旧区域任务标记。`WorkerPreferences` 通过建造、MiningScheduler 和附加任务调度限制个人资格，原任务持料可交付；`WorkerEquipment` 原子交换玩家实际库存与工人原生护甲/副手槽，保护运输主手。

`Residences.details` 给出真实房间检查，`ResidenceOrders` 验证归属/距离/权限并处理命名、入住与自动分配；Living schema 2 与独立 ColonyPreferences schema 1 保持严格迁移及坏数据保留。工作协议 4 要求双方同版；性质及可替换选择见 [0029](decisions/0029-selection-item-sweep-worker-and-home-settings.md)。
