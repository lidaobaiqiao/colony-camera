# 0001：单工程与功能边界

- 日期：2026-10-03
- 状态：采用

## 背景

Forge 1.20.1 视角原型 `0.1.0` 已获得用户正常运行反馈。项目将继续发展为“玩家自定义结构，再规划殖民地”的模组，需要长期维护，但目前只有一个客户端视角功能。

## 决策

保留单 Gradle 工程、`dev.colony.camera` 根包及 `colonycamera` ID。按 `client.camera`、`client.input`、`client.screen` 分离镜头状态与控制、按键、界面。镜头数学和状态抽为无 Minecraft/Forge 依赖的 `CameraState`，适配代码处理游戏事件及生命周期。

当前全部游戏功能只在客户端加载。未来预设、规划与施工分别承载设计、建造意图及执行状态；世界修改由服务端执行。现在只记录这些边界，不为未实现功能创建空模块、接口或网络框架。

## 理由

单工程保持 Forge 构建和调试简单，功能分包使职责明确；纯 Java 状态便于验证数学约束。稳定模组 ID 避免无必要地改变已有安装、资源和按键命名空间。后续再根据真实调用关系增加抽象，避免先维护没有用途的框架。

## 代价与验证

包边界靠代码和审查维持，不由 Gradle 子工程强制。状态计算可自动测试，但摄像机、输入和退出恢复仍需游戏验证。重构必须检查新类进入最终 JAR，并重新验收，不能以 `0.1.0` 的反馈替代。

若未来独立发布 API、跨加载器复用或依赖隔离产生明确需求，再记录新决策并拆工程。
