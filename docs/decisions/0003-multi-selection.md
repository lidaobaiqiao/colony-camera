# 0003：多选状态、分帧框选与两角立体选择

- 日期：2026-10-03
- 状态：采用

## 背景

用户已确认 0.1.5 选中效果生效。后续预设捕获需要选区集合，同时支持可见表面的画面框选与包含遮挡内部的立体范围。摄像机仍为客户端功能，选择不改变世界。

## 决策

纯 Java `SelectionState` 保存去重集合与 G 追加开关，默认下一次操作替换，追加时取并集；每次操作保存开始时的模式，按 FIFO 串行处理。所有成功操作原子提交，集合上限 8192，超限保留原选区。

普通模式左键松开提交，移动达到 4 个物理像素视为框选。`MarqueeSelectionJob` 冻结松开时的逆 `P × V` 与相机位置，分帧在主线程查询已加载世界，每帧最多 128 条射线、约 2 ms。以 32 像素根网格共享四角和中心五个样本；混合命中细分到 2 像素，全空细分到 6 像素，同一方块命中五点后停止。总射线最多 262144，复杂度失败不提交部分集合。

V 切换两角立体模式，允许两角之间操作镜头。闭区间包含两角，最多扫描 8192 格（含空气），结果仅选非空气方块，包括遮挡内部；遇到未加载区域整体拒绝。提交前按完整范围再次核验覆盖区块的加载状态与世界边界，扫描期间区块卸载也会拒绝提交并保留旧集合。Delete 清空并取消未完成作业与排队操作。失焦取消作业、队列、拖动和未完成两角，保留已选集合；退出重置模式与集合。

`SelectionBoxes` 将完整方块精确合并成贪心长方体，不填洞；异形方块保留实际形状。输出形状缓存每帧最多处理 256 项、约 1 ms；目标失效检查每帧最多 64 项。时间预算是软限制，单个世界查询无法中断。

## 取舍

框选通过屏幕射线选择可见表面，采样间、亚像素或被同一背景五点包围的极小目标可能漏选。它不保证枚举矩形内所有可见方块；缩小范围或放大画面可改善捕获，需要准确包含内部时使用立体选择。射线与集合限额为主线程负载提供边界，仍需测量实际 FPS 和复杂场景耗时。

分帧结果以冻结画面确定采样方向，世界继续运行。选择作业、输入队列、缓存与已提交集合分别管理，避免取消后旧作业重新提交；客户端数据不写入原版远程交互路径，不执行挖放或发送世界修改。

## 验证

状态、范围、采样续跑与限额失败、轮廓合并和洞保留由纯 Java 测试覆盖。实际输入阈值、重绑定、预览、模式切换、分帧渲染和失焦取消需按 [回归清单](../testing.md) 游戏验收。0.1.5 用户反馈不替代本版本验证。
