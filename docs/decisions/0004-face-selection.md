# 0004：沿命中面框选，再沿法线选高度

- 日期：2026-10-04
- 状态：采用；替代 0003 中的屏幕采样框选与两角立体交互

## 背景

用户指出 MC 是三维世界，屏幕上的二维矩形与旋转后的空间范围不一致。框选应从鼠标实际选中的方块面出发，沿这个面扩展；立体选择应在同一底面上再选择高度。

## 决策

普通模式保持左键单击单选。鼠标左键按下时记录方块实际命中面及面坐标，达到拖动阈值后成为面框选；拖动中的世界射线与该固定平面相交，交点在面内两轴取 floor 定位格子，法线轴保留起点格所在层。矩形包含起点与终点格，预览在世界中画出贴合该面的四条边，不再绘制 GUI 矩形。真实面可以位于半砖或台阶的半格位置，不强制改为完整方块外壳。

纯 Java `FaceSelection` 统一处理六个轴向面、射线求交、底面格子范围及沿法线延伸。当前悬停块变化和镜头运动不会更换已捕获的底面。平行、后向及非有限交点拒绝更新；游戏适配层拒绝方块内部起始命中、非实际面命中、越界鼠标与超距离交点。无效释放不能借用上一次有效交点提交。

V 立体模式复用同一底面。左键拖动底面并松开后进入高度阶段，滚轮选择沿面法线的有符号层数，下一次左键点击确认。绝对层数包含底面的一层，最少一层、禁止零层；正方向沿面法线向外，负方向向内。上表面向外为向上，下表面向外为向下，墙面对应 X/Z 方向厚度。高度阶段中键平移、右键旋转和键盘镜头运动可继续，底面保持固定；滚轮暂时选择高度，确认后恢复缩放。

普通框选扫描单层范围，立体选择扫描多层范围；两者均按闭区间逐格查询非空气块，包括当前镜头看不到的成员。每个范围最多 8192 格，空气计入扫描体积；选区集合最多 8192 个成员。主线程每帧最多扫描 256 格、约 2 ms。扫描前与提交前整体核验加载区块、世界高度和世界边界，失败保留旧集合，不提交部分结果。

保留 `SelectionState` 的替换/追加原子提交、串行队列和 0003 中的轮廓缓存。中键或右键介入取消底面拖动，高度阶段保留；失焦或窗口缩放取消底面、高度、扫描及排队操作，保留已提交集合。Delete 清空并取消，退出 SLG 重置会话。

## 取舍

面框选表达方块格子范围，不表达屏幕中所有可见物体。底面固定后，前景遮挡或另一高度的块不会改变选择平面；面内范围仍按格子扫描。台阶面预览可处于半格高度，选区成员仍是整个方块坐标，后续黄框使用 OUTLINE 形状显示。

立体模式的“高度”相对于所选面的法线，因此墙面操作实际上选择厚度。这样可统一地面、天花板和墙面，HUD 与使用文档需要说明向外/向内及底层计数。这个版本只选择本地已加载世界，不能借此进行远程挖掘或施工。

分帧预算限制扫描数量并提供时间软上限，单次世界查询不可中断，不能保证实际 FPS。旧版源采样作业与测试从当前模块移除，0.1.6 的旧发行包及验收记录保留。

## 验证

纯 Java 测试覆盖六个面、固定平面与半格面、负坐标、平行/后向交点、反向拖动、正负层数和坐标溢出，以及不同镜头旋转投影还原出的同一世界范围。实际鼠标事件、底面/高度阶段、预览和取消时序按 [0.1.7 回归清单](../testing.md#017-面框选与高度回归) 游戏验收。
