# 0009：可达资源与分阶段仓储

日期：2026-10-04。状态：采用用户确定的玩法要求。1.2.0 实现地面施工，1.3.0 实现可升级仓储与统一端口取料；以下保留完整玩法目标，实际范围及尚待实现的闲置入仓、搜索等见 [决策 0011](0011-printing-core-and-storage.md)。

## 用户确定的玩法

施工可用资源包括工人能够到达并拾取的地面掉落物，以及能够到达并取出的仓储物资。仓库不是开工条件；前期没有箱子时，工人应能直接捡料施工。

仓储随殖民地发展分为三个阶段：地面资源 → 可升级箱子 → 统一存储网络。箱子同时支持格子数量与单格堆叠上限升级；中期通过统一端口存入、查询和取出网络物资。工人不必逐个翻找网络内的箱子。网络保持有限容量，首版围绕统一存取实现。

工程优先度和同级创建时间顺序沿用现有约定，资源预约与运输服从同一调度。

## 可达与可用

“发现资源”“确认可达”“已经预约”“工人持有”是不同状态。按物品及其 NBT 区分材料，不能仅按注册名合并，也不能把需要加工的原料直接当成成品。投影的方块组成仍须转换为真实施工物品账单。

可达性相对于具体工人及任务判断：工人能够走到拾取点或仓储交互站位，取料后能够到达有效施工站位，并且持有取用权限。距离近不代表可达；网络中的资源通过可达端口领取，不要求工人走到每个存储节点。

资源统计显示已知总量、可领取量、预约量、运输中数量，以及不可达或待验证的数量。可领取量是已确认可达、允许提取、尚未预约的资源；网络有多个可达端口时，同一库存只计一次。已经从来源取出的物资只记录在工人运输库存中，不再计入来源。

服务器在已加载世界中分批发现资源，寻路按预算验证并缓存；路径和地形变化后重新检查。未扫描或未加载区域不能凭空计入可领取资源。具体作业范围和刷新预算在实现时确定，不对整个世界逐 tick 全量寻路。

地面掉落物会移动、合并、被玩家拾取或消失。预约绑定来源身份及数量，不等于复制物品或永久锁定实体。实际拾取前重新校验；来源变化后释放或重新绑定预约，重新寻找材料。不能让两个工人同时领取同一份材料，失败也不能无限等待不存在的掉落物。

## 工人的取料流程

调度分配工程及材料 → 选择可执行的取料来源 → 前往取料点 → 服务端实际拾取或扣库存 → 携带到施工站位 → 消耗并建造。

同一工程允许混用地面材料、独立箱子和网络端口。为施工直接拾取的材料可以送到工地，流程不强制先存仓库；剩余物资再按仓储策略整理。相同调度条件下可依据路径成本选择来源，路径成本不改变工程优先度。

工人的搬运容量独立于仓储堆叠倍率；升级箱子不能让工人一次背走全部库存。取消任务释放尚未领取的预约；已经领取的物资继续实际保存在工人身上，之后归还仓储或成为真实掉落物，不能只修改账面数量。

## 可升级箱子

实现时优先提供可从原版箱子升级的殖民地仓储箱，保留内容、名称及朝向。格子扩容与堆叠升级分开计算；升级等级、配方、倍率和对不可堆叠物品的规则尚未确定。扩容保留现有内容，降级或拆除堆叠升级会溢出时先拒绝操作并说明原因。

堆叠倍率只作用于该仓储容器；普通玩家背包、地面物品和工人搬运仍遵守各自的容量及物品规则。容器内数量采用明确的整数持久化与同步，不依赖普通 ItemStack NBT 的 Count 字段承载大堆叠。库存汇总用 long 并校验加减与容量边界；向普通库存、漏斗和地面输出时分批转换成合法物品栈。

仓储菜单必须支持大数量显示、部分取出、Shift 转移、鼠标携带、漏斗交互及重启恢复。升级和持久化只由服务端执行，不通过客户端直接改变数量，也不全局修改 Item 的堆叠上限。

## 统一存储网络

最小方案为连接后的存储节点与存取端口，由服务端维护连通关系和统一物品索引；是否需要独立控制器及连接方式在实现阶段确定。物品实际保存在存储节点，端口查询及取用同一网络库存，端口数量不会复制物品或增加存储容量。单独使用的早期仓储箱可以作为后续网络节点接入，已有物资无需玩家逐箱搬迁。

网络内存取由系统路由到有空间或有目标物品的节点；工人只执行到端口的实体搬运。网络连接内的路由与工人在地面搬运分开处理。统一端口可使用物品列表、搜索及数量显示，避免把所有远端格子拼成巨大的箱子界面。

接入网络的箱子不再作为独立来源重复发布；多个端口共享网络身份和预约账本。断连、拆除、区块卸载或提取规则变化时更新索引并复查预约，物品继续存在于原存储节点。无法读取的节点不发布为可领取库存，首版不强制加载区块。

该阶段先实现有限容量、统一查询与存取，不安排 AE 的自动合成、频道、能量及跨维度系统。玩家若需要这些玩法，再独立评估。

## 实现顺序与验收

1. 建立工程材料账单、可达资源来源及真实取料流程；没有任何箱子时，工人能捡起地面材料并完成一个简单结构，无法绕行到达的隔墙或封闭区域材料不冒充可用材料。
2. 接入独立箱子及升级仓储箱；工人能够从地面和箱子混合取料。格子扩容、堆叠升级、部分提取、降级拒绝和重启恢复均守恒，不丢失或复制物品。
3. 接入统一网络；早期箱子保留物资并成为节点，工人在可达端口存取，多个端口不会翻倍统计。满仓保留未存入余量，断连或卸载后受影响材料明确等待或重新分配，重连恢复可用性。

资源预约、实际拾取/扣除、库存变化和施工修改全部由服务端校验与执行。客户端负责操作意图和状态显示。开发到具体阶段时再引入相应类、网络消息和菜单；本决策不创建占位模块，也不改变 1.1.0 产物。
