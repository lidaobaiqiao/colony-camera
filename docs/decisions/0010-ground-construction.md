# 0010：从地面资源落实工程

日期：2026-10-04。状态：1.2.0 已实现地面阶段，客户端验收待完成。

## 问题

投影只有规划显示。首个施工版本必须在没有仓库时，按工程优先度安排工人真实取料并落实玩家的预设，不能将附近物品数量直接当成库存，也不能凭方块清单免费放块。

## 决策

- 双方安装同版模组。客户端提交投影快照与管理意图；服务端验证归属、数量、实际角色距离、已加载区域、世界边界、建造权限和工程重叠。请求 GZIP 压缩后上限 32000 字节、解压后上限 256 KiB UTF-8，兼容原版 32767 字节服务端单包限制；每玩家每维度最多 32 个工程、32768 个预设方块。
- 工程优先度 1–9 降序，同级用服务端单调创建序号。分配工人和材料都走同一排序；路径预算全局 40 次/调度、单工程至多 16 次，缺料或不可达的高优先工程不阻止其他可执行任务。
- 地面资源先发现，再核验原版拾取冷却与目标归属、数量、路径和拾取视线。每次实际拾取前验证从拾取位置到工地站位的后半程路径；扫描 24 格，寻路最大 64 格并缩小到完整已加载窗口，不强制加载区块。
- 预约用来源 UUID/工人 UUID/工程 UUID 和数量，不改变物品。真实拾取后释放预约，携带库存保存在工人 MAINHAND（实体标准 NBT）；每单元携带 1 或 2 件。优先度变化可重新分配持料；材料类型不匹配时先将真实持料掉回世界。
- 服务端每 5 tick 推进实体任务，每秒或任务状态变化后重排。限时路径失败、来源消失和施工冲突释放任务重试。缺料时自动等待补料。
- 建筑物品与方块不能按数量一一假定：门/床组成一个施工单元并消耗一件，双层半砖消耗两件。液体/含水、重力块、双格植物、无直接 BlockItem 对应或不完整配对暂拒绝创建。
- 不覆盖其他已有方块。放置前复查站位、支撑、实体占位和权限；使用 BlockSnapshot 与 Forge 放置事件。失败恢复快照，成功后再消费携带物品。没有破拆、脚手架或特殊模组放置回调适配。
- 工程 SavedData schemaVersion 1 保存预设快照、归属、优先度、创建序号、暂停/取消与完成位图。未知或损坏数据进入只读并原样保留；瞬时预约和寻路不保存，重载后重新调度。
- 工程 UI 在已有预设面板中增设工程页。测试招募免费，在角色附近安全位置生成工人，以最多 8 个已加载工人作为原型入口；居民生存与经济不在本次范围。

## 使用与代价

本地投影和服务端工程是两份快照；修改投影不能偷偷搬动工地，删除投影不能取消施工。取消工程保留已建方块和真实持料；记录可在完成/取消后移除。

当前物资只来自地面、须为无额外 NBT 的匹配建筑物品。箱子建成为空，机器内部数据不复制；动态方块状态和第三方回调需后续适配。工程 UI 的附近计数表示发现的目标材料，不能冒充已经确认可取用的全部殖民地库存。

后续普通箱子、格子/堆叠独立升级仓储箱及统一网络遵循 [决策 0009](0009-reachable-resources-and-storage.md)。本实现未复制上游源码、没有 Litematica、IronChest、SophisticatedBackpacks 或 AE 运行时依赖。

## 验证

纯 Java 测试验证排序与预约互斥。独立 `src/gameTest` 源集在真实 Forge 服务端验证拾取/运输/放块、优先/FIFO、补料、隔墙不可达、来源消失、暂停与 NBT 保存、门床/半砖账单、保护拒绝回滚和未知存档保留。测试世界新建于 `build/game-test-run`，测试类和模板不进入发行 JAR。

服务端测试不证明实际客户端 UI、实体渲染、多人传输或光影兼容；这些在 [游戏验收](../testing.md) 中单独记录。
