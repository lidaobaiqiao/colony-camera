# 决策 0012：挖掘、清扫、科技与殖民地生产

日期：2026-10-05。状态：已实现（1.4.0）。

## 背景

选区已经能表达玩家规划的表面和体积，但只有建造任务时，殖民地仍不能处理工程前的清场、矿物采集和工具供给。材料又不能只按“箱子里有多少”判断：掉落在地面、由工人实际走得到的物资也属于可用资源。工作顺序必须和已有建造统一，否则高优先工程会被低优先生产抢走库存。

## 决策

- 挖掘和清扫都是服务器保存的有界任务。客户端只提交已确认的方块或包围盒；服务端复查归属、加载状态、交互权限、原方块状态和预约，玩家替换方块后跳过该成员，不把新方块当成旧任务目标。
- 挖掘使用真实的副手工具和原版生存破坏流程。工人按挖掘等级、工具材质和方块硬度决定是否可执行，破坏成功后才获得经验；耐久、附魔、名称、原版掉落和 Forge 保护事件都保留。施工与清扫物资仍放在主手。
- 清扫把选区包围盒及顶面上一格内的掉落物分两段处理：先通过 Forge 拾取事件拿到主手，再把主手物品交给玩家自有仓储或连接有效的网络端口。满仓、断连、拾取冷却、权限或路径失败时保留地面物品或主手持料，不凭空删除。
- 合成台和研究台只接受工作站周围三格内、已加载、属于玩家且工人能从工作站站位触及的仓储或网络端口。分配与执行使用同一站位复查遮挡；事务先在副本库存中预演扣料、产物和配方余料，完成 tick 再复查原库存与预约并原子提交，异常时回滚。生产读取服务器现有的十三个有序原版配方：木棍及木、石、铁、钻石镐/斧/铲。
- 1.4.1 在此基础上加入九种殖民地设施与升级件的工人生产，总计二十二种配方。设施/升级件均为科技零级，避免合成台、研究台或仓储依赖自身生产/研究能力；初始设施可由玩家在原版工作台制作，配方书由原版库存进度自动解锁。工人和玩家读取同一服务端配方，数量和配方余料保持一致。
- 科技按维度和玩家保存，研究逐级消耗真实库存材料，控制工具等级和工人的使用门槛。未知或损坏的科技/任务存档进入只读保护并原样保留。
- 建造、挖掘、清扫、合成和研究共用 `ConstructionManager` 的创建序号、工人池和 `ReservationLedger`。优先度按 9 到 1 降序，同级按创建序号 FIFO；批量预约是原子的，阻塞任务让出工人，实际提取/破坏/提交前再次验证。

## 取舍与边界

工作站只发布本地三格内的自有库存，网络仍是有限的加载区块、单控制器、面连接组件；没有实现 AE 式频道、能量、跨维度或自动合成链。清扫是一次性有界任务，不是全图闲置收集器。批量挖掘拒绝方块实体、液体和不可破坏方块，设施需玩家手动拆除。

## 验证

1.4.0 的 143 项 JUnit、45 项 Forge GameTest 和 ECJ 3.46.0 空值检查覆盖工具领取/磨损、等级边界、立体挖掘、地面掉落清扫、满仓与断网持料、木棍/木镐合成、研究扣料、封闭仓储与执行中遮挡、跨任务优先度/FIFO、事务回滚和坏数据保护。客户端交互、真实多人、第三方容器兼容及性能仍需独立实机验收。

1.4.1 保留上述回归，新增四项服务端场景，共 49 项通过。全部九种设施/升级件已逐一验证生存工作台制作及材料触发配方书解锁、零级科技目录与工人真实库存生产，连接块整批容量不足时不扣料。普通服务端玩家用于进度解锁验证；真实客户端与多人验收仍独立记录。
