# 0014：寻路探查隔离与清扫完成条件

日期：2026-10-06。状态：采用，1.5.1。

## 发现

用户反馈不同工种原地发呆。原版 PathNavigation.createPath 不只是返回一条路径：还会更新导航目标和卡住计时，并可能复用正在执行的路径。原来的站位/取料可达性查询共用执行导航器，探查 B 后再次查询 B 会拿到正在走向 A 的旧路径。新增服务端回归在旧代码上明确失败。

多工人清扫也存在独立错误：空手工人看不到地面掉落时便设为完成，没有等待另一名工人手里的最后一批货物入仓。旧开发存档只读检查发现完成清扫后仍持有货物的工人，新增多工人测试在旧代码上失败。

## 决定

每个工人使用独立 LoadedGroundNavigation 作规划，只用它查询可达性，不为它提交执行路径。规划查询不能修改真正执行导航器的路线、目标和卡住计时。浮水设置保持一致。GroundResources.follow 在启动移动时由执行导航器针对已验证目标创建并提交路径，使原版重寻路仍以正确目标执行。所有路线仍限制在已加载区域，不传送工人或加载远程区块。

清扫只有在地面无目标且同属殖民地的工人均无持料时才可完成。空手工人让出调度，持料工人继续申请入仓路径；优先度、FIFO、真实持料、预约和容量检查保留。历史任务已标记完成时不强行修改存档，玩家可重新下达清扫处理残余持料。

新增测试置于独立 GameTest 批次并清理自己的测试工人，避免临近场景的实体影响已有物品/站位测试。实际多地形、客户端及卡顿验收仍需游戏测试。
