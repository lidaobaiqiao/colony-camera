# 0018：工人持料保存任务归属

日期：2026-10-06；状态：采用；版本：1.6.1。

## 问题

清扫用所有同属工人的非空主手判断运输与完成。较早的未完成清扫因此会接管后来建造工程已经领取的材料，安排入仓；重新调度后工人再次领料，形成反复运输或等待。真实物品仍在，但工程无法稳定推进。

## 决策

- WorkerEntity 增加可选任务 UUID，以 ColonyCargoTask 随实体 NBT 保存。主手仍是真实物品，归属仅用于跨任务协调，不成为虚拟库存或数量预约。
- 建造领取材料或接收匹配持料时标记工程，清扫领取/接收归仓材料时标记清扫。主手完全消耗、成功归仓或成功生成真实掉落后清理；导航重排、暂停、满仓、断连和读档保留。
- 清扫只等待该任务的持料，保护未完成和暂停建造及其他未完成工作任务的材料。取消、完成或找不到原任务的持料允许归仓。普通优先度/FIFO 调度和实际取用校验继续执行。
- 旧工人没有归属标签：优先延续现有清扫配送；否则匹配同属殖民地、导航范围内未完成施工单元所需物品及数量，恢复建造归属；无匹配时按遗留清扫材料处理。恢复不寻路、不加载区块、不移动或消费物品。

## 保存与边界

标签缺失即旧版，不升级工程 SavedData 或网络协议。新版保存由 Minecraft 正常保存工人实体时执行，不离线改写玩家世界。旧数据只记录了物品，没有其来源；若旧清扫持料恰好也是邻近工程所需材料，优先恢复为施工持料，避免建造被清扫反复截走。归属不是任务预约，不保证阻塞工程必然存在路径或材料。

## 验证

服务端回归覆盖旧无标签材料、较早阻塞清扫与后续长距离建造、暂停保护/取消归仓、真实清扫及 NBT 往返；旧无标签材料回归在修复前失败。正式数量和客户端验收边界见 validation/1.6.1.md。
