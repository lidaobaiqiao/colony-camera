# 0019：稳定挖掘顺序与路线续行

日期：2026-10-06。状态：采用，1.6.2。

## 问题

用户反馈工人跳着挖、经常停工和原地不动。1.6.1 的目标排序按高度和工人距离重新计算，但把游标当成这份动态待挖列表的偏移：完成、移动或其他工人认领目标后，偏移会指向另一块方块。预算提前耗尽时仍前进 64 项，短列表可能回到原点，永远不检查后面的可达目标。

同一任务按工人实体顺序重新派工，较早的空闲工人会先认领另一名工人正在开的块，后者改派并失去累计进度。任务间优先度正确不能弥补任务内部的这种抢占。

站位规划使用固定 1.5 眼高，执行用真实眼高，两种射线可能对遮挡得出不同结论；粗略到位范围也不足以证明实际视线或已离开准备挖掉的支撑块。旧代码会立即释放视线被遮挡的任务，再分配同一站位。

清扫/合成每秒重启同一目标的路径，GroundResources.follow 每次都调用原版 moveTo。已核对本地 1.20.1 原版源码/字节码：moveTo 会重设 lastStuckCheck 和 lastStuckCheckPos，持续调用会使静止检测无法积满所需时间。

最后一个导航节点也沿用宽松的途经点容差：工人尚未走到能看到河床的站位，导航就结束。随后重新寻路会先朝当前格中心移动，再向目标格靠近，重现“路线仍在、半格内反复起步”的停滞。真实流水挖掘测试的失败信息确认目标为同一站位、下一节点正确，但工人停在站位前；独立终点回归检测这个过早结束。

## 决定

- 无在途目标时，从高层、同层就近、固定 X/Z 顺序挑选可用方块；有有效在途目标则继续它。成功分配后移除扫描续点，下一次恢复正常优先选择。
- 预算/分帧扫描只保存原始目标索引，每工人独立；按实际检查数量续扫，不能使用动态列表偏移或共享扫描偏移。续点只在内存中存在，读档重新规划，不新增存档格式。
- 同一任务内正在工作的工人先续派，空闲工人取剩余目标；跨任务仍由统一优先度/FIFO 分配，可受更高优先任务抢占。暂停、取消、损坏数据和受保护方块的规则继续保留。
- 规划与执行使用相同真实眼高。到位半径内没有实际视线时继续向已验证站位移动；站位本身失效则释放重选。工人身体仍在目标块上方时先离开，不能挖掉自身支撑。
- 目标相同且路线未结束时直接续行，不重复调用 moveTo。到达、原版检测卡住、目标变化或世界更新触发的导航重算仍按原版进行；不传送工人，不穿墙、不强制加载区块。
- 最后一个节点保留原版垂直到位、绕角和卡住检测，仅收紧水平终点容差到格中心 0.1 格；尚未达到时继续该终点，不启动一条经过上一格的新路线。普通途经点仍使用原版跟进规则。
- 任务显示保留成功分配工人的活动状态，避免后一个无法工作的工人把整个任务状态覆盖为阻塞。

## 验证边界

先在旧实现上增加五个服务端复现场景，五项均失败。该次完整 75 项运行另有一个旧施工测试失败，必须如实记录，不能把它算成新增挖掘缺陷的证据。

后续再增加脚下支撑、双工人立体开采和路线终点测试，共八项新增回归，运行完整独立 GameTest、发布构建和空值检查。最终结果见 [1.6.2 验证记录](../validation/1.6.2.md)。复杂深坑、封闭区域、外部模组实体干扰和原世界实机恢复仍需单独确认；这里没有实现自动修路/搭桥或任意深水潜泳。

首次修复后七项新场景通过，完整运行另有清扫恢复和两项流水测试失败。只读检查该测试世界确认一处水渠被自然天花板掉落的沙砾取代，不据此直接修改工人物理。GameTest 启动时改用无结构/装饰的超平坦生成，仅写 `build/game-test-run/server.properties`，后续新测试世界按这个固定前提重新验证；玩家世界和存档不变。
