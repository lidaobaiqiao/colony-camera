# 0023：挖掘分工与进度保存

日期：2026-10-06。状态：采用。实现版本：1.8.0。

## 必须成立的结果

沿用 [0021](0021-mining-algorithm-baseline.md) 的性质：目标独占、单块进度守恒、真实工具和生存破坏、权限与精确状态复查、实际站位/视线、导航隔离及坏数据保留。暂停、换位、工人更换和读档后，已做的部分工作应保留；几何分工不得阻断原有优先度和同级 FIFO。

## 实现选择（允许推翻）

1. 开放面来自真实世界，不把选区之外当成空气。完成一块后增量更新邻居；周期复查外部变化。候选站位必须具备支撑、空间和真实眼高视线，禁止使用目标块本身作为站位支撑。
2. 工人优先使用当前安全站位连续处理可见的目标，再按覆盖量、实际破坏时间估计及移动距离选择下一站。干地局部排序考虑已有进度、暴露程度和高度；脚部浅水关闭高层剥离偏好。头部浸水不作为站位，等待排水；不引入自动排水或潜泳。
3. 以工作量和能力划分连续空间分工，剩余区域完成或工人集合变化时调整。分工是偏好，其他工人可以接手；已经认领的块仍保持独占。受阻站位和规划失败暂缓重试，地形变化后重新评估。
4. 进度按工程目标索引积累，每 tick 至多推进一次。`WorkTask` 中的进度只是执行检查点，不能用新任务的零值覆盖工程已有进度。以上容器、排序、周期与路径探查预算均可替换，不是长期约束。

## 存档变更与迁移

0021 本身不改变格式。本实现为了满足跨读档的部分进度保留，明确升级附加任务 SavedData 到 schema 3；不修改预设、投影、施工或仓储格式，也不改变网络意图。

- MINE 任务新增整数数组 `miningProgress`，以目标索引和进度成对保存，只有非零项。
- schema 1/2 保留目标、精确状态、完成位图、优先度和暂停状态；旧版没有可恢复的部分进度，迁移时从零开始。原来的空气成员不移除，避免改变完成位图索引；新任务受理时才排除空气。
- 索引越界、重复索引、奇数长度、进度不在 1–10000、已完成目标带部分进度，或 schema 3 缺失该字段，均拒绝整个数据，原样只读保留。未知版本同样保留。
- schema 3 不支持旧版读取。升级前备份；回退模组必须恢复升级前备份，不能把新存档交给旧版强行重写。

## 对照与测试处置

0021 要求的 8×4×8 石体、三名南侧石镐工人使用真实服务端执行。1.6.2 在 90000 tick 后只有 192/256，未取得有限完工时间；因此不声称测得精确“新/旧完工时间比”。新算法须完整完成，并满足不高于观测下界的 60%；记录真实 tick、移动距离、经验、耐久和掉落。原始结果与复现信息见 [1.8.0 验证](../validation/1.8.0.md)。

0019 的两项游标/预算测试改写为“认领块排除”与“不可达站位不得饿死可达工作”，不保留旧游标行为断言。独占目标、实际视线、脚下支撑、路线续行和终点到位继续验证；新增连续站位、交接、抢占、暂停、保存迁移和坏数据保留。

## 边界

本次只替换挖掘调度与部分进度持久化。0022 的脚手架施工尚未实现；清扫、合成、科研、仓储和界面沿用现有行为。没有自动修路、搭桥、深水排水或处理选区外的遮挡方块。
