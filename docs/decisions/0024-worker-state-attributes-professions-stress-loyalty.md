# 0024：工人状态层（属性、兴趣、职业、压力、忠诚）

日期：2026-10-06。状态：**采用**。定位：**玩法基础，最先实现**。

本文件是工人 AI 的**输入契约**。0021（挖掘）、0022（建造）以及后续的任务调度都消费本文件定义的数值。
状态层必须先行：算法是"给定异质能力求最优分配"，能力定义不了，调度无从谈起。

写作口径与 0021/0022 一致：**写必须成立的结果，不写具体数据结构**。

**已定数值（用户确认）**：属性无上限、出生 1、约 7 游戏日 +1 点；压力 0–100；
效果映射逐属性独立，**禁止全局统一倍率**。

**核心设计坐标**：压力与忠诚是**两根方向相反的轴**（成本 vs 资产）。本设计刻意区别于
同类模拟经营中"只有一根单向怨恨轴"的做法（详见 5.0），**善待必须可积累、恩义必须可兑现**
（S7b）。

## 一、设计原点（用户定义）

> **是模拟经营，但要最优解。二者不冲突。**

用户的"像人"定义与常见做法不同：

| | 常见做法 | 本设计 |
| --- | --- | --- |
| 差异来源 | 随机数、故意犯错 | **个体能力不平均** |
| 与最优解的关系 | 冲突 | **不冲突** |
| 表现 | 会绕路、会犹豫 | **同样尽力，但起点和能力不同** |

**核心推论**：

1. 不用随机数制造差异（那是假的）
2. 用**出生加成 + 属性成长速度 + 职业 + 工具限制**制造差异
3. 每个工人在**各自能力的约束下做到最优**
4. **"测试人属性最高"是问题**：所有工人同一起点、同步成长时差异被抹平，观感就是同质化机器

**分工结论**：模拟经营提供异质性，算法负责在异质性下求全局最优。

## 二、属性系统

### 2.1 两层属性（用户确定）

| 层 | 属性 | 作用域 |
| --- | --- | --- |
| **基础属性** | 生命值、饥饿值、防御力、移动速度、攻击力 | 实体物理存在 |
| **职业属性** | 挖掘速度、建造速度、搬运速度、携带容量、心理承受力、制造速度 | 工作能力 |

**关键：职业属性不是职业专属。** 所有工人都有这两层属性；职业只改变**成长速度**。

### 2.2 成长机制（用户确定）

> **没有上限。所有人的属性都可以练到满。差异来自成长速度。**
> **职业属性永远大于其他属性——因为不同职业的成长速度不同。**
> **时间足够 → 全能选手。这是耐心者的奖励。**

**这一条是设计基石，必须理解正确**：

| 项 | 规则 |
| --- | --- |
| 上限 | **无**（属性可以无限叠加） |
| 出生值 | **默认 1**（兴趣/性格可带来出生加成） |
| 差异来源 | **成长速度**（斜率），不是天花板 |
| 职业的作用 | **加速特定职业属性的成长** |
| 终局 | 可以全能，代价是时间 |
| 玩家体验 | 投资与耐心，不是取舍与遗憾 |

**"职业属性永远大于其他属性"是过程保证，不是终局状态。** 终局可以全能，但前提是投入足够时间。

**推论（影响后续调度设计）**：调度算法必须读**当前属性数值**，而不是职业标签。两个矿工的挖掘属性可能一个是 3、一个是 47。

### 2.3 数值刻度与成长速率

**刻度：无上限整数点数。** 属性是一个可以一直增长的整数，不用等级封顶、不用 1–10 区间。

- **出生值默认 1**；兴趣与性格可以带来出生加成（见第三章）。
- **UI 直接显示属性点**（例："挖掘 47"），不折算成 Lv。
- 不设 1–10 之类的封闭刻度，因为设计前提是"所有人都能练满、且可以继续练下去"。

**成长速率（用户确定）**：

> **属性成长是缓慢的。预计游戏内一周才能提升一点。**

| 项 | 值 |
| --- | --- |
| 基准速率 | **游戏内 7 天 ≈ 1 点**（MC 一天 20 分钟 → 约 2.3 小时专精工作得 1 点） |
| 量级参照 | 100 点 ≈ 233 小时专精工作 → 100 点是**终局目标**级，不是中期目标 |
| 加速来源 | **职业**（对应职业属性成长更快）、**性格**（固定增减益）、**学堂**（加快学习速度） |

**"一周 +1 点"是基准斜率，不是最终斜率。** 职业加速、性格、学堂加成全部乘在这个基准之上。
职业属性的点数之所以长期领先其他属性，就是因为它享受职业乘数。

### 2.4 成长触发（用户确定）

**两条路径，都可累积**：

| 路径 | 说明 |
| --- | --- |
| **做对应工作** | 挖掘 → 挖掘速度经验；放置 → 建造速度经验；搬运/取料 → 搬运速度经验。**做什么涨什么** |
| **学堂主动学习** | 学堂提供主动学习，可以直接推进属性成长（见 4.4） |

**做什么涨什么是硬规则**：不允许"挖矿却涨了建造"。它保证了玩家能从行为预测成长方向，
也保证了调度算法可以把工人"练"成想要的形状。

**效果映射（用户确定：不做统一百分比）**：

> **不同工作、不同属性，对效率的增益各有各的曲线，不能用一条统一公式。**

- 效果映射表**按属性分别定义**（挖掘一套、建造一套、携带容量一套……），不存在全局倍率。
- **首版全部使用占位系数，数值留到平衡阶段再填。** 本文件只要求"接口按属性分开"，
  不允许实现成一个共享的 `globalMultiplier`。
- 早期占位建议：线性起步（每点 +1% 量级），便于观察与调参，但**必须逐属性可独立配置**。

**为什么不做统一映射**：携带容量是离散的物品数、心理承受力是压力阈值、挖掘速度是进度累积率，
量纲完全不同，共用一个公式必然要在某个属性上做假。

### 2.5 属性清单

**基础属性**（用户列出，5 项）

| 属性 | 影响 |
| --- | --- |
| 生命值 | 实体血量上限 |
| 饥饿值 | 食物消耗与饱食上限 |
| 防御力 | 受伤害减免 |
| 移动速度 | 行走与奔跑速度 |
| 攻击力 | 近战伤害 |

**职业属性**（用户列出 6 项）

| 属性 | 影响 |
| --- | --- |
| 挖掘速度 | 破坏方块的进度累积率 |
| 建造速度 | 放置方块的动作时长 |
| 搬运速度 | 取料/入仓的动作时长 |
| 携带容量 | 单次可携带的物品数量（**直接影响往返次数**） |
| 心理承受力 | **压力上限与压力恢复速度** |
| 制造速度 | 合成与研究的耗时 |

**每个属性各自一套效果映射**（见 2.4），互不共享公式。

**待用户补充的候选**：研究速度、攀爬速度、感知范围。当前不纳入，留接口。

## 三、兴趣（= 性格的集合）

### 3.1 定义（用户确定）

> **兴趣不是独立维度。兴趣包含多个性格，并限定自身可选择的职业。**

```
兴趣（例：科学家）
  ├─ 包含的性格：冷静、聪明、好奇……（每个性格带一对增益/减益）
  ├─ 允许的职业：研究员、工匠……（兴趣限定了能学什么）
  └─ 性格组合有约束（"科学家"不可能是"暴躁"）
```

| 概念 | 层次 | 性质 |
| --- | --- | --- |
| **兴趣** | 宏观类别 | 决定可学职业 + **出生属性加成** + 性格分布范围 |
| **性格** | 具体特征 | **一条固定增益 + 一条固定减益** |

### 3.2 兴趣与出生属性（用户确定）

**工人出生时默认全属性 1，兴趣与性格是唯一打破这个起点的东西。**

> **"默认为1，对于性格兴趣有加成。"**

这是差异化的第一个来源（第二个是成长速度、第三个是职业）：

| 来源 | 作用时机 | 作用方式 |
| --- | --- | --- |
| **兴趣** | 出生 | 直接抬高该兴趣相关属性的出生值 |
| **性格** | 出生 + 全程 | 出生时抬高压低相关属性；全程提供固定增益/减益 |

**关键：出生加成只影响起点，不影响斜率。** 出生高的人只是起步早，出生低的人一样能追上——
这维持了"无上限、耐心者奖励"的前提，不构成隐形天花板。

### 3.3 性格规则

- 性格**不是必定获得**（可选）
- 性格是**一对**（+1 增益，−1 减益）
- 性格**固定不变**（不随成长变化）
- **增益与减益都作用在"效果映射"的输入或输出上**，不是直接给属性点数

示例（**增益/减益的具体量与载体待平衡，此处仅示意结构**）：

| 性格 | 增益 | 减益 |
| --- | --- | --- |
| 急躁 | 移动速度效果 + | 制造速度效果 − |
| 沉稳 | 心理承受力上/恢复速度 + | 移动速度效果 − |
| 细心 | 建造速度效果 + | 挖掘速度效果 − |

**为什么性格不做成连续属性轴**：连续轴会与属性混淆；离散的成对特征是一个**标签**，语义清楚，且天然有取舍。

## 四、职业

### 4.1 获取机制（用户确定）

```
所有工人默认【无职业】
    ↓
需要【住所】（一人一间，硬性一对一）
    ↓
住所满足 + 学堂满足 → 可以学习该职业
```

| 要素 | 说明 |
| --- | --- |
| **住所** | **一人一间**。工人数量 = 住所数量，是殖民地规模瓶颈 |
| **学堂** | 学习场所，本身有等级，承担**职业门槛**与**主动学习**双重职能（见 4.4） |
| **双重门槛** | 学堂等级 + 住所条件，都要满足 |
| **不同职业门槛不同** | 高价值职业要求更高 |

**住所是硬需求，不只是学职业用。** 这给了殖民地建设一个基础驱动力：不管想干什么，先让工人有地方住。

### 4.2 软门槛（用户确定）

**核心原则：不设硬属性门槛，只设软代价。**

| 条件 | 达标 | 不达标 |
| --- | --- | --- |
| 学堂 | **必须满足** | 无法学习 |
| 住所 | **必须满足** | 无法学习 |
| 属性 | **额外加成** | **可以强行学习**，但有减益 + 压力 |
| 兴趣 | **额外加成** | 同上 |

**这是本设计的关键机制**：把"门槛"从二元判断变成**代价选择**。

- 传统做法：属性不够 → 不能学（玩家被挡住）
- 本设计：属性不够 → 能学，但**代价高**（玩家自己权衡）

### 4.3 职业可更换、可叠加（用户确定）

| 状态 | 条件 |
| --- | --- |
| 单职业 | 学堂 + 住所 |
| **更换职业** | 允许。**已获得的成长保留** |
| **双职业（双学位）** | **更高级学堂 + 更严苛属性要求 + 巨大压力** |

**双学位的压力仅在学期间**，学完获得**属性增益**（不是惩罚）。

**"攻读双学位"** 是一个高投入高回报的选择，不是惩罚机制。

### 4.4 学堂的双重作用（用户确定）

> **"学堂等级能开发更高级的学习，也能加快学习速度。"**

学堂的作用分**两层**，一层是量、一层是质，缺一不可：

| 层 | 作用 | 说明 |
| --- | --- | --- |
| **量** | **加快学习速度** | 学堂等级越高，主动学习与成长越快的倍率越高（低级学堂即可享有） |
| **质** | **开发更高级的学习** | 高等级学堂**才能开启**新内容：更高级的职业、双学位资格、更高段的专项课程 |

**"开发更高级的学习"是解锁，不是加成。** 它意味着低等级学堂无论投入多少时间都到不了某些目标——
这是**唯一允许的、由设施（而非属性）构成的硬门槛**，因为它是玩家可以建设的，不是天生的。

### 4.5 学堂主动学习（用户确定）

除"做对应工作"外，**学堂提供第二条成长路径：主动学习**。

| 项 | 说明 |
| --- | --- |
| 作用 | 直接推进属性成长，不必依赖实战积累 |
| 速度 | 受学堂等级的**加快学习速度**影响 |
| 内容 | 受学堂等级的**开发更高级的学习**限制 |
| 价值 | 让"练属性"成为一件玩家可以主动安排的事，而不是只能被动等工人干活 |

**这条路径的存在意义**：它让"投资学堂"成为一个有明确回报的决策——
干活的成长是顺带的，学堂的成长是专门买的。两条路径并存，玩家可以自由配比。

## 五、压力系统（玩法基础）

### 5.0 两根方向相反的轴（设计坐标，先读这一节）

**压力与忠诚不是"两个数值"，是两根方向相反的轴。这一点是本设计区别于同类游戏的地基。**

```
压力轴：工人对我的亏欠感   ↑ 差   ↓ 好     短期 · 可见 · 可归因 · 可修复
忠诚轴：我积累的恩义储备   ↓ 无   ↑ 有     长期 · 只能养 · 危机才掉 · 可兑现
```

| 项 | 压力 | 忠诚 |
| --- | --- | --- |
| 方向 | 越低越好 | **越高越好** |
| 性质 | **成本**（玩家持续投入以压制） | **资产**（玩家持续投入以积累） |
| 时间尺度 | 短期，随生活状态波动 | 长期，缓慢单向积累 |
| 玩家角色 | 亏欠方 | **被记恩的一方** |

**为什么必须是两根轴**：

同类模拟经营（如《冰汽时代》）**只有一根单向的怨恨轴**——不满只能被压制、被延缓，
玩家永远处于"亏欠并挨骂"的位置。玩家做了医院、供了暖、喂饱人，系统给出的回执是
**"不满 −15"**，是一次成本回收，**不是一笔存款**。善意在该系统里**单向流失，无回流机制**。

后果是：市民只会索取，不会承认恩情；玩家的全部经营心力没有任何"沉淀"去处。

**本设计补上回流机制**：善待 → 忠诚积累 → 在极端时刻可兑现（特殊指令）。
这不是多加了一个数值，而是把**单轴对抗**换成了**双轴经营**。

**推论（约束后续所有设计）**：

1. 压力可修复（见 5.1–5.3），忠诚**只能靠生活变好增长**（见 6.1）。
2. 忠诚**只在压力爆满时下降**——保证平时善待能存下来，不被日常摩擦悄悄磨掉。
3. 忠诚必须有**明确的兑现出口**（见 6.3 特殊指令），否则积累没有意义。
4. 不允许出现"只知道索取、不承认恩情"的行为模式（见 S7b）。

### 5.1 压力来源（用户确定）

| 类别 | 具体来源 |
| --- | --- |
| **职业相关** | 强行攻读不达标职业；做不擅长的工作 |
| **生活质量** | 吃得不好；生活环境差 |
| **疲劳** | 睡眠不足 |
| **无休** | 劳动时间长；没有休息时间 |
| **指令抗拒** | 收到超出自身忠诚的特殊指令（见 6.3） |

### 5.2 压力数值量纲（用户确定）

| 项 | 值 |
| --- | --- |
| 压力值域 | **0–100** |
| 罢工阈值 | **100**（压力满） |
| **压力上限** | **由心理承受力等级映射** = 压力阈值随承受力提高 |
| 恢复 | 随心理承受力等级映射的恢复速率 |

**"上限 = 承受力等级映射"的正确读法**：

心理承受力不是"降低压力值"，而是**抬高能承受的阈值**。实现上推荐：

```
有效压力比 = 当前压力 / (100 × 承受力系数)
罢工条件   = 有效压力比 ≥ 1
```

这样 UI 可以统一显示 0–100 的百分比，而"这个工人的 100 分相当于别人的 60 分"这层差异
通过**承受力系数**表达。玩家看到的是同一个刻度，比较的却是不同的承受量。

**取舍**：也可以做成"压力 0–100 固定、承受力只影响恢复速率与降忠诚速度"。
本文件不锁定这两种实现，只要求**压力必须可视化为 0–100**、**承受力必须实际生效**。

### 5.3 压力恢复与可见性（用户确定）

- **可恢复**（休息、改善生活）
- **玩家可以看到每个工人的压力源**，并针对性修复

**"可见压力源"是硬要求**。它把压力从黑盒变成可管理的指标——否则玩家会觉得工人"莫名其妙罢工"。

### 5.4 罢工（用户确定）

> **压力满 → 工人罢工 → 在心情平复之前什么都不做。**

**罢工是 AI 行为**（工人自主决定不干），不是"玩家下令"，也不是"AI 无法干"。

### 5.5 心理承受力与压力的关系

**心理承受力 = 压力上限 + 压力恢复速度**（用户确认方向）

- 承受力高 → 不容易满，恢复快
- 承受力低 → 容易罢工

这也是"双学位需要严苛属性要求"里的关键一项。

### 5.6 对已有算法的影响（必须回填）

**压力系统不是独立模块，它反向约束 0021 与 0022**：

| 文档 | 原目标 | 修正后 |
| --- | --- | --- |
| 0021 | 尽快挖完 | **在不触发罢工的前提下**尽快挖完 |
| 0022 | 尽快建完 | 同上 |

**推论**：调度需要引入**轮换**——限制单工人的连续工作时长，在高强度任务间轮替工人。

## 六、忠诚系统（玩法基础）

### 6.1 数值规则（用户确定）

| 项 | 规则 |
| --- | --- |
| 默认值 | **0**（中性，**无任何影响**） |
| 下限 | 默认不低于 0 |
| 负值 | **设计上存在**，当前版本**不做**，留接口 |
| **降低条件** | **只在压力爆满时下降** |
| **增长条件** | **只在生活变好时增长** |

**这意味着忠诚是一个"纯正向的解锁度"**，不是满意度：

- 低忠诚 = 没有特权（但不受罚）
- 高忠诚 = 解锁执行特殊指令的资格

**关键：忠诚是玩家唯一能"积累"的东西。**

同类游戏中玩家只能**延缓损失**（压制不满）；本设计中玩家可以**积累资产**（养忠诚）。
这是 5.0 双轴模型的直接后果，也是本设计与"刁民类"设计的分水岭。

### 6.1b 恩义必须可兑现（用户确定）

忠诚轴存在的意义，取决于它**有没有兑现出口**。若只有积累没有兑现，
它就退化成第二根不满轴——涨得不明不白，玩家照样算不清账。

**兑现出口**：忠诚足够者会执行玩家的特殊指令，**甚至不反抗**。

> **忠诚者被处决时不会反抗，因为他足够忠诚。**

这一条是整根忠诚轴的**压力测试**。它证明忠诚不是"讨好感度"（玩家讨好工人换取好处），
而是**一份双向契约**：玩家给了恩，工人认了这份恩——认到可以拿命来还。

**由此产生的硬约束**：

| 约束 | 理由 |
| --- | --- |
| 忠诚必须能**长期持有**，不被日常摩擦磨损 | 否则玩家攒不下来，"积累"名不副实 |
| 忠诚的兑现必须是**玩家主动选择的时机** | 恩义由玩家支取，不是系统随机消耗 |
| 忠诚不足者**不得表现为"受恩而不知"** | 低忠诚只表示"尚未足够"，不表示"忘恩负义" |

**第三条的说明**：低忠诚工人不是"刁民"。他们只是**还没有被培养到那个程度**。
本设计不产生"受恩却反咬一口"的行为模式——这是刻意排除的。

### 6.2 压力与忠诚的耦合（关键）

```
压力爆满  →  忠诚度下降（压力是忠诚的腐蚀剂）
生活变好  →  忠诚度上升（生活质量是忠诚的营养）
```

**"压力爆满才降忠诚"** 意味着：**忠诚只在真正的危机中流失**，平时的小压力不会消耗它。这让忠诚成为**耐受力储备**。

**这一条同时是对玩家的保护**：它保证了"平时善待能存下来"。若忠诚会因日常小摩擦缓慢流失，
玩家的投入就永远留不住，那与只有怨恨轴的设计没有区别。

反馈回路：
```
低忠诚工人收到特殊指令 → 压力↑ → 压力爆满 → 忠诚↓ → 更不服从 → 更易崩溃
```

**该回路必须被量级约束**（见十一节"需要单独确认的分支"）：处决的连带影响若失控，
一次事件就清空玩家长期积累，忠诚轴会重新退化为"只能损失、不能积累"，
回到 5.0 要摆脱的那个设计。**这是本设计最需要守住的一条数值红线。**

### 6.3 特殊指令（用户确定）

**共同规则**：

| 规则 | 内容 |
| --- | --- |
| AI 自主性 | **AI 不会自主发起**（一切指令来自玩家） |
| 目标 | **可对任何人发起** |
| 执行 | **只有忠诚足够者才执行** |
| 抗拒 | 忠诚不足者收到 → **压力增加** |
| 目击范围 | **必须是 AI 亲眼所见**（真实视线，不是半径） |
| 信息控制 | **被动规则**（系统自动判断有无目击者） |
| 传播 | **目击者是否传播，由其忠诚度决定** |

**重要澄清**：AI 的"不自主"**仅限特殊指令**。工人本身有自己的 AI——会自主执行任务、做生理行为、日常活动。只是**不会自己决定去执行处决或献身**。

**处决**：

- 只对**旁观者**有影响
- **无目击者 → 不会被认定为处决**（信源在玩家手中，AI 只能相信）
- 忠诚者被处决时**不会反抗**（他足够忠诚）

**目击链必须显式记账（防止重新长出黑盒）**：

处决的影响沿目击者传播，若无约束会产生连锁崩溃：

```
处决一人 → 多名目击者压力↑ → 有人爆满 → 忠诚↓ → 更易爆 → 连环罢工
```

若放任该链，玩家会看到"处决了一个人，然后三个不相干的人莫名罢工"——
这会让忠诚轴重新变成不可预测的黑盒，**并与 S7b 直接冲突**。因此必须：

| 约束 | 内容 |
| --- | --- |
| **单次冲击有上限** | 每个目击者受到的是**一次、非叠加**的压力冲击，不得"看到就爆" |
| **二次传播必须衰减** | 由传播者转述给他人时，冲击**必须小于**一次目击 |
| **压力源单独列出** | UI 中必须是独立条目（"目击了处决"），不得混进"生活质量" |
| **总消耗有上限** | 单次事件的忠诚总损失必须有上限，**不得清空玩家长期积累** |

**第四条是数值红线**（见 6.2 末与第十一节）：忠诚的价值建立在"能积累"之上，
任何一次事件都不允许把这条积累抹掉。

**献身**（切尔诺贝利式）：

- **本身没有代价**——代价来自执行时的**真实危险**（辐射、岩浆、摔落、爆炸）
- **会鼓舞士气**，提升**临时增益**
- 成功与失败给**不同的增益**
- **对低忠诚者无效**

**献身的设计定位**：它是**必要的**（极端情况下用忠诚储备换取更大利益），不是为了满足玩家私欲的惩罚手段。

### 6.4 忠诚作为资源

综合 6.1–6.3，玩家的核心博弈是：

```
建好殖民地（住所/食物/设施）
    ↓
忠诚度增长（储备积累 —— 这是玩家唯一能积累的东西）
    ↓
用储备执行特殊指令（处决/献身）
    ↓
滥用或生活变差 → 储备枯竭 → 无忠诚者可执行
```

**忠诚是玩家最珍贵的资源**：只能慢慢积累，只会在危机中流失。

**与其他设计的分界**：在只有怨恨轴的同类游戏里，玩家的经营心力没有任何沉淀去处，
市民只会索取、不会承认恩情，玩家的位置永远是"亏欠并挨骂"。
**本设计里，善意有去处、恩义有记账、兑现有时机。** 这是 S7b 要守住的东西。

## 七、性质清单（必须永久成立）

### S1 属性是算法输入
- 所有影响工作能力的属性必须被算法实际消费；不得存在"只显示不生效"的属性
- 调度读**当前数值**，不读标签

### S2 无上限成长
- 属性不设硬上限，**可以无限叠加**
- 出生默认 1，兴趣/性格可带来出生加成
- 不引入"潜力点数分配"之类的天花板机制
- 差异只能来自**出生加成 + 成长速度 + 职业**

### S2b 成长缓慢且可预测
- 基准速率：**游戏内 7 天 ≈ 1 点**
- **做什么涨什么**：不允许"挖矿涨建造"
- 成长有两条路径：做对应工作、学堂主动学习

### S3 职业只改速度不改上限
- 职业加速特定职业属性的成长
- 职业不封禁其他属性的成长
- 职业可更换，已获成长保留

### S3b 效果映射按属性分开
- 每个属性有独立的点→效果映射表
- **不允许全局统一倍率**（量纲不同，统一必然造假）
- 首版使用占位系数，数值留待平衡
- 出生加成只抬高起点，不改变斜率

### S4 职业获取受设施约束
- 无住所 → 不能学职业
- 学堂等级不足 → 不能学对应职业
- 属性/兴趣不达标 → **可以学**，但有减益与压力

### S4b 学堂双重作用
- **加快学习速度**（量）
- **开发更高级的学习**（质，解锁型硬门槛）
- 后者是唯一允许的、由设施构成的硬门槛

### S5 压力可归因
- 每个压力来源必须**可被玩家看到**
- 不允许存在无法解释的压力增长（否则玩家会认为工人"莫名罢工"）

### S6 压力必须可恢复
- 所有压力来源都有对应的恢复途径
- 罢工不是终点，是可恢复状态
- 压力统一可视化为 **0–100**，罢工阈值 100
- 心理承受力**必须实际生效**（抬高可承受阈值或加快恢复）

### S7 忠诚单向依赖生活质量
- 忠诚降低**只由压力爆满引起**
- 忠诚增长**只由生活变好引起**
- 忠诚不影响日常行为（0 时无任何影响）

### S7b 忠诚是可兑现的恩义
- **玩家必须拥有两根方向相反的轴**：压力（成本，越低越好）+ 忠诚（资产，越高越好）
- 忠诚必须能**长期持有**，不被日常摩擦磨损
- 忠诚必须有**明确的兑现出口**（特殊指令），否则积累无意义
- **不允许出现"只知道索取、不承认恩情"的行为模式**——这是刻意排除的同类游戏毒点
- 低忠诚表示"尚未足够"，**不表示忘恩负义**；不得产生"受恩却反咬"的行为

### S8 特殊指令不自主
- AI 永远不自主发起特殊指令
- 只有忠诚足够者执行
- 忠诚不足者收到指令必然增加压力

### S9 信息即事实
- 处决的认定以**目击者亲眼所见**为准
- 无目击者时不影响任何工人
- 传播由目击者忠诚度决定

### S10 数据完整性
- 存档变更引入 `schemaVersion` 并定义迁移
- 未知或损坏数据进入只读保护并原样保留
- **属性、压力、忠诚、职业、兴趣必须随实体持久化**

## 十、实施顺序

**状态层必须最先落地**，因为它是所有算法的输入契约。

| 步 | 内容 | 验收判据 |
| --- | --- | --- |
| 1 | **属性字段与持久化**（`WorkerEntity` 扩展 + schemaVersion 迁移） | 11 项属性随实体存读；出生默认 1；旧存档迁移后不丢数据 |
| 2 | **属性 → 效果映射表（按属性分开）** | 每属性一张独立表；无全局统一倍率；首版占位系数可调 |
| 3 | **成长触发：做对应工作** | 挖掘/建造/搬运各自累积到对应属性；**无错配** |
| 4 | **把 `MiningSkill` 并入属性系统**（A1） | 独立经验制删除；挖掘速度由属性表驱动 |
| 5 | **压力系统**（来源、恢复、0–100、可见性、罢工状态） | 每个压力源可被玩家查到；罢工是 AI 自主行为 |
| 6 | **忠诚系统**（因压力爆满而降、因生活变好而涨） | 0 时无任何影响；降低只由压力爆满触发 |
| 7 | **住所设施**（一人一间 + 工人绑定） | 工人数受住所数约束 |
| 8 | **学堂设施**（学习速度倍率 + 高级学习解锁 + 主动学习） | 两条成长路径都可用；高级内容低等级学堂拿不到 |
| 9 | **职业获取**（单职业 → 更换 → 双学位） | 软门槛生效：不达标可学但有减益与压力 |
| 10 | **兴趣与性格**（含出生加成 + 限定职业 + 增益减益对） | 出生值可被兴趣/性格抬高；出生加成不改斜率 |
| 11 | **特殊指令**（处决、献身 + 目击判定 + 传播） | 无目击者不认定为处决；低忠诚者不执行且压力增加 |
| 12 | **UI**（人物页：属性点直显 / 压力源 / 忠诚 / 职业 / 兴趣） | 压力条 0–100；属性直显大数字（"挖掘 47"） |

**第 1–3 步是唯一的最小可玩闭环**：属性存在、属性生效、属性会涨。这三步做完，
"异质工人"就已经成立，后续调度才能开始消费它。

## 十一、边界

本文件定义**状态层**，不定义算法（见 0021/0022/0025）。

当前不做（留接口）：
- 忠诚的负值区间
- 研究速度、攀爬速度、感知范围（用户未确认）
- **具体的属性→效果数值**（首版占位，平衡阶段再填）
- **具体的工作量档位**（研究阶段再定）

已定但需在实现中保持：
- 属性无上限、出生 1、约 7 游戏日/点
- 压力 0–100、阈值 100
- 效果映射逐属性独立，**禁止全局统一倍率**

需要单独确认的分支：
- **处决对旁观者的具体影响量**：需要平衡，否则可能出现"处决一人 → 多人压力上升 → 连环罢工"的雪崩
- **献身的临时增益**：具体数值与持续时间待定
- **压力与忠诚的联动速率**：压力爆满多久降一点忠诚
- **职业加速倍率的相对关系**：不同职业之间怎么排序

**数值红线（S7b 的直接推论，不可违反）**：

忠诚的价值建立在"能积累"之上。任何单次事件（尤其是处决目击链）的忠诚总损失
**必须有上限**，不得清空玩家长期积累。一旦违反，忠诚轴退化为第二根不满轴，
本设计将失去与同类游戏的区别。调整任何与忠诚相关的数值前，先确认这一条没有被突破。
