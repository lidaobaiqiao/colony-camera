# 0028：清扫目的地与实际入仓连续性

日期：2026-10-08。状态：1.10.2 已实施，自动验证结果另记。继续遵守 0024 的属性输入契约与 0027 的精确顶面、物资守恒性质。

## 问题与必须成立的结果

当前清扫在每次调度时从工人当前位置重新搜索仓库和选择站位。工人离开默认 24 格搜索范围后，可能忘记已选目的地并在去往掉落物途中停下；距离变化还会重选另一侧站位并终止当前路线。入仓强制要求距格子中心不超过 0.1 格，也会让已经实际可操作的工人继续等待。

1. 已经合法选择的拾取来源、仓库与站位应保持连续，直到来源、路径、权限、容量或任务条件变化；仅出现更近候选不能不断打断正在执行的路线。全局优先度、FIFO 和预约仍优先于保留旧任务。
2. 暂停、休息或读档清掉临时任务后，实际持料与归属保持；明确的殖民地清扫意图可以重新定位导航范围内的已加载自有仓储/端口，不能因临时目的地丢失而永远发呆。
3. 真实距离、视线、取用权限与仓储容量证明可以入仓时，不要求精确对齐某个格子中心。需要继续接近时仍走真实导航；不到可操作位置就不能存放，不传送、不远程修改仓储、不强制加载。
4. 障碍、仓库归属变化、满仓和断连必须复查。无效旧目标应让出或重新规划；持料及 NBT 不丢失，不从另一任务偷取预约或交付物。

## 当前可替换实现选择

- `SweepService` 优先保留同任务未过期的来源 UUID、目的地与取用站位；在优先度顺序重建预约时重新检查来源数量、顶面成员、归属和实际可取路径。
- `WorkPaths.beside` 接受可选旧站位，只在仍可站立、能操作且可达时复用。旧站位不成立才检查其他候选；独立规划导航器不改动执行路线。
- 活动任务继续使用已选的已加载仓库。当没有临时目的地时，`StorageResources.colonyStores` 在工人导航范围内查找已加载自有仓储/网络端口，至多 128 个候选；普通材料/食物扫描继续使用原搜索范围，殖民地设施恢复不扩展其他资源扫描。
- 拾取和存放的实际距离/视线成立后停下导航再推进搬运动作，避免边移动边重新选点。存放保留现有三格取用范围及真实仓储事务，不以宽松到位半径替代视线。
- 当前旧路线的期限仍为临时调度字段；没有给 SavedData 或工人 NBT 增加目的地缓存。恢复时依据已加载世界重新验证设施，世界退出无静态目的地残留。
