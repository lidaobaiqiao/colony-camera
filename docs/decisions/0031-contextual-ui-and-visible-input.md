# 0031：按需详情与可见界面的输入所有权

日期：2026-10-17。状态：1.13.0 首轮落地。设计来源为 [UI 系统规划](../ui/ui-plan-2026-10-14.md)，既有双端底栏、中键工具循环和八个独立建造窗口继续成立。

## 必须成立的结果

- 普通对象检查不能把整个场景当成弹窗；其余世界区域仍允许合法的镜头和选择操作。真正模态的打印、装备选择和确认窗口独占输入。
- 可点击区域必须与当前可见控件一致。窄屏列表/详情互斥时，隐藏格子和提交按钮不接受点击；返回保留当前对象和列表位置。
- 菜单、帮助与检查器叠放时，绘制更高的层先消费输入；背后的控件不悬停、不收按键、不提交世界操作。
- 字体按实际宽度处理，长内容可换行、滚动或查看完整提示；不能只靠缩小字号把全部信息挤进窗口。
- 查看或更换界面布局不更改世界、库存、任务优先度、科技和人物状态。所有修改仍提交原有服务端意图并经服务端验证。
- 特殊指令确认绑定选定的工人与目标，不允许更换列表选项后把旧确认提交到新目标。

## 允许调整的实现选择

人物采用右侧、按内容收缩的检查器；正常尺寸六页分两行，最窄尺寸使用页名和前后按钮。打印与特殊指令确认使用独立模态布局。属性、学习、生活和关系从概况移到各自页签。

任务、配方与科研在 GUI 宽度低于 520 时采用列表/详情切换；配方列表一次最多 20 项，保持既有服务端检查批量边界。科技依然只有八个真实节点，效果与阻塞原因放在材料清单前。

共享 UiTheme/UiDraw 只集中实际重复的绘制功能；布局保持纯 Java。输入路由继续由现有屏幕负责，不预先增加通用控件框架或服务端协议。像素数、断点与颜色都可根据实测调整。

范围、未实施部分与验证边界见 [1.13.0 实施记录](../ui/implementation-1.13.0.md)。
