## 1.6.1 单选、紧凑界面与施工恢复

1. F6 进入 SLG，工具栏单选高亮；点击连续石墙中的一块只选一块，HUD 为 1 且黄框匹配该形状。再点另一块替换；G 追加后点不同材料累加、重复点击不重复计数，点空处按追加开关保留或清空。
2. 切相似后仍扩展 26 邻接同类方块，并遵守上限；切回单选不扩展，相似上限不影响单选。工具切换保留既有选区但取消未完成扫描/选高；右键单击仍清空、拖动仍平移。
3. 单选→V→V 返回单选；相似→V→V 返回相似。清空后保持当前工具；退出再进入恢复单选。默认键及重绑定的立体切换分别检查。
4. N 选择方块进入连续建造，点击底部任一选择工具退出未放置草稿，接下来左键选择而非继续下单；已有工程继续执行。V 键也能退出草稿。预设调整时检查同样行为，编辑草稿取消后原已保存投影保留。
5. GUI 320×180、400×225、640×360：左侧建造目录不遮住画面中心，最小尺寸仍显示方块；类别下拉、颜色、悬停材料、搜索、可建筛选和右键收藏可用。左键图标直接进入放置，下方仅留一条 26 像素工具条。打开目录解除未放置草稿，不删除已受理工程。
6. 目录内部操作不选择世界；面板外滚轮缩放、右键平移、解锁后的中键旋转可用，点击外面后 WASD/升降可用，搜索框聚焦时不会把文字当移动。空选区、闲置提示和标题消失，其原区域可正常点击；有选区时只有一行数量，状态结束后消失。帮助、任务、预设、上限对话框保持原来的模态归属；失焦、缩放、退出取消未完成选择。
7. 阻塞较早清扫（例如密闭墙内有掉落物），再安排较晚建造，观察工人真实领料、运输、施工，不反复把建造材料放回仓库。空清扫不等待建造持料；多工人真正清扫仍等待最后的运输入仓。暂停工程、满仓、断连、取消及重进后检查持料守恒。对 1.6.0 原世界检查已持料工人继续施工；离线不修改该世界文件。
8. 在草丛和藤蔓上放目录工程，投影定位在植物所在格并由工人消耗材料替换；固体和含水状态仍冲突、不覆盖，普通预设仍使用严格空位规则。蓝色工作站自动合成后建造和绿色成品建造分别检查。

自动检查见 validation/1.6.1.md；此列表仍需客户端实机验收。

## 1.6.0 建造目录与自动合成

1. 双方安装同版，F6→N/建造按钮，搜索中文名称、英文 ID、模组命名空间及多词。类别、收藏、可建筛选、滚动/键盘选择在 GUI 320×180、400×225、640×360 下命中一致；首次查询为灰色，查询完成后显示颜色与状态文字。

3. 在自有工作站三格内摆仓库/端口，放一块橡木原木；木板变蓝，缺原料/工作站、路径不通或仓库无输出容量时变红。地面原料需清扫入库；普通箱子不充当当前站点生产仓储。
4. 选择方块、世界左键下单，只出现投影且资源未立即变化；工人真实取料/合成/建造。一原木产四木板，建一格后剩三件入仓。绿色直接取成品，支持的红色工程等待成品；不支持类型有说明且不能选择。
5. 连续放置、R 旋转、PgUp/PgDn 调高度、方向键微调、滚轮缩放、中键旋转和右键平移；UI 内操作不能透传给镜头/世界。Esc 取消草稿、N 重选目录；原 B/P/O 与普通预设流程继续正常。
6. 门、床任意四个方向完整配对，消费一件。已有方块冲突标红等待，不覆盖；工程重叠、超加载/权限/数量等拒绝不留前置任务，失败回复后保留可调整草稿。打开 P/帮助时建造草稿工具条不遮挡面板、不抢点击。
7. 给两个工程不同优先度，确认生产前置按父工程优先度且同级 FIFO；在 P 工程页或 O 关联供料任务暂停/取消/改优先度时双向同步，不吞已存在真实材料，低优先任务补料后恢复。
8. 保存退出、重进或多人重连：建造投影、进度、优先度和生产关联恢复；旧 schema 1 正常读入且保留原项目；损坏/未知数据仍只读且保留。完成/取消工程不再绘制投影。

## 分层验证

| 层次 | 要证明什么 | 不能证明什么 |
| --- | --- | --- |
| 纯 Java 状态测试 | 平移、归一化、缩放范围、边界约束等计算正确 | Forge 事件实际触发、画面及输入恢复 |
| Gradle 构建 | Java 编译、资源处理、打包和混淆任务通过 | 游戏加载和交互正确 |
| ECJ 空值分析 | 主源码、测试源码的空值契约及可能为空的访问检查通过 | 所有运行时状态及模组交互都安全 |
| Forge 服务端 GameTest | 工人实体、物品守恒、寻路、实际世界放置、事件保护和数据重载 | 客户端输入/画面、真实多人网络与全部模组组合 |
| JAR 检查 | 入口、拆分后的类、语言文件及访问转换器进入交付包 | 安装实例加载了该包 |
| 安装核验 | 交付 JAR 与测试实例 `mods` 中的 JAR 相同 | 运行效果正确 |
| 游戏内验收 | 摄像机、按键、生命周期在真实客户端工作 | 所有光影或其他模组组合都兼容 |

纯 Java 测试围绕边界和不变量：斜向与轴向平移速度一致；缩放达到上下限后仍保持范围；超出水平活动半径时正确限制；无输入不移动。不要只断言方法调用自己产生的值。

当前 `CameraState` 使用 JUnit Jupiter，运行 `.\gradlew.bat test`；构建使用 `.\gradlew.bat build`。`build` 同时执行 `verifyArchitecture` 与 `verifyModJar`，检查边界及包内容。`scripts/build.ps1` 的交付归档位于 `dist/<version>/`，附 SHA-256 与 `verification.json`。摄像机无法通过无界面单元测试完整验证。

选择的纯 Java 测试覆盖原子并集/上限、闭区间整数边界、轮廓合并不填洞、六面固定平面、正负高度层数、26 邻接、拐角链、空隙和不同类型阻断、广度优先截断、单步查询预算、变化/卸载拒绝及整数极值。测试不能证明真实鼠标、Minecraft 世界适配、弹窗输入或实际 FPS，需游戏测量。

## 游戏内回归清单

使用测试存档和独立测试实例，记录 MC、Forge、模组版本，以及是否有光影或其他摄像机模组。

1. 第一人称进入世界，切换键进入 SLG，确认默认角度锁定、60° 俯视画面、鼠标自由显示。
2. 锁定时中键拖动不旋转；WASD 和右键仍可平移，滚轮仍可缩放。斜向速度一致，Shift 加速；角色没有因这些按键行走。
3. F7 解锁，中键拖动改变朝向与俯角；上下限 15°/85° 不翻转，水平角度连续绕圈。旋转后 WASD 按当前镜头朝向移动，右键拖拽使画面跟随鼠标；不同 GUI 缩放下灵敏度一致。
4. F7 重新锁定保留当前角度且再次禁止旋转；长按 F7 不连续切换。重新进入 SLG 恢复默认角度锁定。滚轮缩放到上下限、平移到活动范围边缘，画面保持稳定。
5. 空格/C 上下移动，只改变镜头高度，不改变角色位置、俯角和缩放距离。锁定/解锁均可用，Shift 加速；重绑后操作和提示一致，同时按上下键停止升降，斜向+升降没有额外加速。
6. 对照静止、WASD、右键平移、中键旋转和升降时的 FPS 与平滑程度；在 60/144 FPS 下不应出现旧的 20 Hz 台阶运动。拖动中失焦、暂停/退出后恢复时不产生补跑长距离。帧率明显下降需结合实际实例继续分析，不能以数学测试声称 FPS 问题已经解决。
7. SLG 中将鼠标移到角色触及距离外的已加载方块，白框随鼠标准确移动。改变朝向、俯角、距离、FOV、GUI 缩放和窗口比例后，边框仍对应屏幕中目标；检查台阶、栅栏等实际形状。
8. 默认单选模式左键单击只选命中方块并出现黄框，HUD 数量为一并显示名称坐标；切相似才扩展同类邻接方块。追加关闭时点空处清空，目标变空气或区块卸载后分帧移除。
9. SLG 中角色身体、持物、准星和攻击指示隐藏；原位火焰/水下/窒息、南瓜或模组头盔、望远镜及冻结遮罩不干扰镜头，原位玩家视线的旧高亮不出现。其他玩家正常显示，世界继续运行，本地角色仍按原规则受伤。
10. SLG 状态点击鼠标，确认未触发角色挖掘、放置或攻击；右键和中键拖动继续执行镜头操作。
11. 切换键与 Esc 均能返回第一人称，之后可正常移动、转头、挖掘及切换物品；准星、攻击指示、持物与所有上述视野遮罩按当前角色状态恢复，再次进入不保留旧选择。
12. 在按键设置中更改视角切换键与角度锁定键，验证新键工作，界面提示与绑定一致。
13. 连续切换；进入时按住移动键再退出；拖动中切出窗口再回来，确认没有粘键或镜头持续移动，新的鼠标按下才能开始拖动。
14. 从 SLG 离开世界、重新进入；检查视角、晃动选项、选择与输入没有残留。
15. 若出现死亡、重生或界面被替换，确认 SLG 能正常收尾且可以再次进入。

## 0.1.8 表面框选与中键旋转回归

表面框选部分为历史清单，1.5.0 已删除；镜头中键行为继续保留。当前选择按下方 1.5.0 验收。

1. 默认锁定状态下中键拖动不旋转，右键拖动平移；F7 解锁后中键旋转并调整俯角，右键仍平移。确认上下限、当前朝向下的 WASD、滚轮及空格/C 不受交换鼠标键影响，退出后原版鼠标交互恢复。
2. 在同一框选范围中放置平地、坡地、凹坑和不同高度的叠放方块。从上表面左键拖动，参考矩形保留起点高度，蓝色待选轮廓随各列真实高度；松开后每列只选最上面的一个可选方块，数量与列数对应，不遗漏较高/较低目标，也不包含内部叠层。终点停在高台或低谷的实际方块上时，范围应沿该方块的切向坐标结束，不能因投影到起点高度而横向偏移；终点指向空处时仍使用固定面求交。分别从低到高和从高到低重复。
3. 从下表面选择不同高度的悬空结构与洞顶，核对每列选择最下方目标；空列不增加成员。测试六个面、负坐标、跨区块以及反向拖动，面内两轴范围包含起止格，外侧方向跟随命中面法线。
4. 测试半砖、台阶、栅栏、草/花及带液体的表面。实际轮廓非空的方块可入选，空轮廓液体略过后寻找同列下一可选目标；蓝色和黄色描边保持实际形状。参考平面的半格高度仍保留，内部起始命中不能启动面框选。
5. 上表面测试普通地形、地下起点及起点上方结构，核对每列按世界有效高度选最上层，而不是只在起点附近找目标；下表面检查最低有效高度附近与含多个空区段的结构。分别在主世界、下界/自定义高度维度核验高度范围，不能把高度图或跳空区段的单元模拟当作游戏适配已通过。
6. 从四个墙面测试起点前后 32 格范围内不同厚度的结构，每列沿对应外侧取一个目标；范围外方块不得入选。让搜索扩展边缘遇未加载区块，窗口应缩到所有列共用的连续已加载范围，不跨缺失区块选择更远的目标；所框范围本身未加载则整体拒绝。
7. 表面预览和提交扫描期间让依赖区块卸载，确认整个作业拒绝并保留旧选择，不提交已完成列；已选成员的区块卸载后分帧移除。重新加载后需重新发起操作，不能延续使用旧冻结窗口。开发检查应直接核对 `getChunkSource().hasChunk`，不要以本版本恒为 true 的 `ClientLevel.hasChunk` 判断测试区块已加载。
8. 大范围拖动时观察蓝色预览分帧增加，完成后应显示全部真实表面。改变范围或空处无效求交后，不应残留旧范围的预览或误提交。拖住左键等待预览完成，让另一玩家在已有顶块上添加新块或移除顶块，再松开：应重新查询新表面，不提交被埋住的旧块或因旧块移除而漏掉下层。墙面加载窗口应以松开时的状态重新冻结。每帧最多 2048 项/约 2 ms 的预算同时覆盖列范围查询与采样，但必须另记录 FPS、查询与提交耗时。
9. 核对最多 8192 列和最多 8192 个成员的边界；空列也计入范围，超限、世界边界越界或追加并集超限均保留旧集合。G 开关追加并去重，关闭后下一次成功操作替换；操作保存开始时的追加状态并按队列顺序执行。
10. V 模式仍以固定起点面拖底面，松开后滚轮调整沿法线的高度/厚度，再左键确认；此操作不自动跟随地形。范围包含空气且最多 8192 格，确认后选择其中非空气成员，包括遮挡的内部；V 保留旧规则，不使用普通表面的空 OUTLINE 过滤。高度阶段右键平移、中键旋转及键盘移动保持底面不变，滚轮只调层数，确认后恢复缩放；立体扫描每帧仍最多 256 格/约 2 ms。
11. 普通底面拖动时启动右键平移或解锁后的中键旋转应取消拖动；Delete 取消表面预览、提交扫描、排队操作或高度阶段并清空，失焦/窗口缩放取消未完成操作并保留旧集合。F6/Esc、离开世界及界面替换重置会话，旧作业之后不得重新提交。
12. 重绑 G/V/Delete 为键盘或鼠标键，验证提示、连发抑制和输入优先级。所有选择及镜头鼠标操作均不得触发原角色挖掘、放置或攻击。密集表面选区仍检查完整块合并不填洞，异形块不变成完整方块；实机结果按 JAR 哈希单独记录。

## 0.1.9 鼠标高度与缩放回归

1. V 开启后左键拖底面，松开无需继续按住；光标 X 固定，上下移动只调整高度，横向移动不改变底面或层数。再次左键点击确认。普通表面框选仍保持 0.1.8 规则。
2. 鼠标上移向外、下移向内，反向回到底层。核对整数吸附与底面计数；六个面均沿对应法线延伸，上/下表面为 Y 高度，墙面为 X/Z 厚度。绿色轴向外、红色轴向内、黄色标记随偏移移动。
3. 高度阶段让鼠标保持静止，滚轮缩放到不同距离并核对层数、世界底面和选区不变；随后上下移动鼠标继续选高，灵敏度随投影变化。按 WASD/空格/C 移动镜头也不能凭空改变层数。
4. 高度阶段中键旋转（先 F7 解锁）与右键平移须释放横向限制并暂停高度更新。松开后从当前 Y 继续，不把镜头拖动距离加入高度；连贯操作缩放、镜头拖动与选高，确认底面固定、层数无跳变。
5. 改变 GUI 缩放、窗口比例、FOV、俯角及镜头距离，核对原始窗口坐标换算、真实投影灵敏度与轴线位置。接近正视法线或底面移出视野时也应有受限灵敏度，无 NaN 或无限层数。
6. 横向移动触发光标约束后，新 Y 必须保留，不产生旧 Y 回放、反复回调或光标抖动。切换窗口、按 V/Delete、F6/Esc、离开世界或窗口缩放后，鼠标恢复自由，旧高度状态不能继续提交。
7. 选区过大、超世界高度/边界或含未加载区块时保持红色预览并拒绝确认，保留旧集合；鼠标缩回有效范围后可继续确认。G 追加保持开始操作时的模式并去重，确认仍只选非空气成员。
8. 记录实际安装 JAR 哈希及本版本游戏结果。上述 GLFW、渲染和交互不能由纯 Java 测试代替。

## 1.2.0 工程与地面资源回归

自动服务端 GameTest 覆盖：真实拾取运输施工、两名工人竞争一件材料时高优先获料、同级创建顺序、补料恢复、隔墙不可达、来源消失后重新寻找、暂停与持料/工程 NBT 保存、门床/双半砖物品账单、未知数据原样保留、保护拒绝回滚，以及高优先缺另一种材料时不阻塞低优先独立工程。运行命令见 [开发规范](development.md)；这不代替下列客户端验收。

1. 双方安装 1.2.0，单人和测试多人各走一遍：保存小型圆石结构 → 确认投影 → P 的投影页创建工程 → 工程页测试招募 → 实际角色丢料，观察工人走路、手持材料、实际放块与进度。
2. 使用两项同材料工程和不足物资，确认数字大的优先、同级按创建顺序；提升后创建工程的优先度，确认未拾取预约及后续任务改排。已消费的材料不能凭调优先度恢复。
3. 给高优先工程缺少的砖块，给低优先工程足够圆石，确认低优先可完成，高优先补砖后继续。不要用距离远近替代工程顺序。
4. 地面物品在可达处/封闭墙内/高台/水边、拾取冷却和归属限制下逐一检查；搬动物品、玩家先捡走、途中堵路后，不能凭旧预约免费施工，也不能隔墙取料。
5. 暂停正在运输的工程，确认工人停止任务且持料不丢；继续后可完成。取消保留已建方块和持料，随后其他任务可复用；移除记录、编辑或删除本地投影的作用分别核对。
6. 重启/退出重进、卸载并重载工人所在区块，核对工程优先度、进度、暂停/取消、归属与真实持料。工程不强制加载远程区块。
7. 目标有冲突方块、缺支撑、实体挡位或服务器保护规则时，界面原因明确且材料不消失；移开障碍后继续。门/床和双半砖按组计料，旋转/镜像后实际状态正确；不支持的状态应在创建时拒绝。
8. 小窗口/GUI 缩放下三页切换、选中项在优先重排后保留、材料提示与按钮不重叠；面板内点击不穿透为世界选择，滚轮与镜头键保持已有行为。检查中文与英文提示。
9. 其他玩家不能修改自己的工程或使用自己的工人；跨维度/断线重连后不显示旧工程。另一客户端需能看见工人及其真实持料；兼容和网络行为以实际测试结果记录。
10. 当前未实现箱内取料、仓储升级和存储网络，不能将它们登记为通过。记录大量工程与工人下的真实 tick 耗时、FPS 和动态模组方块支持情况。

## 1.3.0 打印、仓储与网络回归

服务端自动场景覆盖已注册创造分页及搜索条目、悬空角色从核心打印并施工、堵塞/外人/冷却拒绝、大数量存取与坏库存保护、普通箱子和仓储取料、实际右键转换及保护回滚、多端口共享库存/断连/补料/优先度以及满仓 Shift 的库存守恒。下列客户端与多人项目尚需实机完成。

1. 双方安装同一 1.3.0 JAR。创造物品栏找到“殖民地”分页，核对五种设施与两个升级件的模型、中文名称及提示，搜索“打印核心”“仓储”也可找到；生存配方按配方文件核对材料与产出。
2. 在平地放置核心，右键打印，再飞行或切换 SLG → P → 工程 →“打印工人”。生成应在核心周围地面；留出两格净空。无核心、周边完全封闭、重复快速打印和八名上限均给出原因。两个不同位置核心应按选中工程的位置选最近者，既有工人继续归属原玩家。
3. 建立一件圆石工程，分别从地面、普通箱子、仓储箱和端口供料，观察工人走到取料点、持料运输及真实放块；角色不必在工地。隔墙封闭、上锁容器或无可达端口时不得隔空取料。大量不可达掉落物不应让已有可达仓储永远无法供料。
4. 用容量升级件右键含物品、改过名且有朝向的原版单箱，确认转成 54 格仓储并保留内容；普通右键不要求蹲下。双箱和上锁箱拒绝并提示；服务器放置保护拒绝时仍为原箱，物品和升级件都保留。
5. 仓储继续升至 81/108 格，再将堆叠升至 2/4/8 倍。普通 64 堆叠物品每格最高 512，不可堆叠工具仍为一件。存满后 Shift 转移立即结束且玩家余料保留；左/右键取用、Shift、快捷栏和丢出不能产生超大背包/地面栈。Shift + 右键拆升级，库存会溢出时拒绝。
6. 菜单按类型与 NBT 分别汇总，大数量与精确悬停数一致；存取超过一页类型后翻页无丢料。检查 GUI 缩放、中文/英文、长名称和窗口变化。拖拽分配/双击收集暂不支持，应无隐藏库存变化。
7. 一个控制器连接至少两个有不同物资的仓储和两个端口，从任一端口统一查询/存入/取出；工人从端口领取封闭仓储的材料。两名工人争一份材料时高优先先，同级按创建顺序；补料后另一工程继续，端口数量不会翻倍物资。
8. 拆连接块、卸载节点区块、恢复连通或添加第二个控制器，确认状态明确，已存物资保持在真实仓储箱；断连时不能凭旧预约免费施工。用漏斗存取仓储与端口，满仓余料留在来源，跨维度及未加载区块不被强制访问。
9. 保存退出、重启服务端并重进，核对仓储大数量、升级、名称、归属、核心和实际工人持料；拆仓储时正常掉落全部内容及升级，输出原生合法堆叠。坏库存只读保护不得覆盖原数据。
10. 另一玩家不能打印或打开自己的设施；测试多人连接、工人持料渲染及原有 SLG 鼠标门禁，按最终 JAR 哈希记录。真实帧率/tick 耗时、光影和其他模组容器/自动化兼容另行实测。闲置工人自动入仓未实现，不能登记为通过。

## 1.4.0 挖掘、清扫、合成与科技回归

服务端自动场景覆盖选区状态复查与立体挖掘、工具领取/等级/耐久、地面掉落清扫、满仓等待、断网保留主手持料、拾取保护、原版配方事务、研究材料与科技保存、建造和生产共享优先度/FIFO、预约竞争、工作站站位及坏数据只读保留。客户端和多人需安装最终混淆 JAR 后实测。

1. 双方安装同一 1.4.0 JAR。在 SLG 中完成普通表面或 V 立体选区，O → 任务 →“挖掘选区”，确认工人按等级和副手真实工具执行；空手及木/石/铁/钻石工具的门槛、耐久、附魔、名称和原版掉落逐项记录。被玩家替换、液体、不可破坏、方块实体和受保护方块不得被批量拆除。
2. 在已选地面区域生成有归属和无归属掉落，分别测试拾取冷却、封闭路线、玩家先拿走、满仓和断开的网络。O →“清扫选区”后，工人先把物品放到主手，再运到自有仓储/端口；目的地不可用时地面物品和主手持料都应保留，重新连通或腾出容量后能继续。
3. 放置殖民地合成台、研究台及三格内的自有仓储/有效端口。右键工作站与 O 面板两条入口都应显示中文配方/科技材料；合成木棍及木、石、铁、钻石镐/斧/铲，检查真实扣料、产物/余料入库、满仓回滚和次数语义。封闭仓储不得隔墙供料，补料或恢复取用通道后应继续。研究逐级消耗圆石、铁锭/煤炭、钻石/红石，保存重进后等级不丢，锁定配方不能绕过科技。
4. 同时创建建造、挖掘、清扫、合成和研究任务，使用相同材料及不同优先度，确认数字大的先、同级创建早的先；缺料时低优先任务可运行，补料后高优先任务恢复。暂停/取消、来源变化、工人离开、工作站破坏或仓储断连不得吞掉材料、工具或已完成结果。
5. 重启服务端并重进，核对工人经验、主手/副手 NBT、任务顺序、科技等级和仓储数量。检查小窗口、中文/英文、长名称和工作面板命中边界；测试多人权限、第三方容器、光影和大规模任务下的真实 FPS/tick，把结果和安装 JAR SHA256 写入验证记录。

## 1.4.1 生存设施合成

服务端新增场景逐一验证九种设施/升级件在原版工作台的配方解锁、产物和扣料，在零级科技的殖民地目录中可见、工人逐一生产，以及连接块整批容量不足时的无损等待。自动场景使用生存模式和有限合成规则，真实客户端还需核对配方书与鼠标交互。

1. 安装最终 1.4.1，使用已有生存存档和新存档分别测试。取得原版工作台、箱子、铁锭、红石、铜锭，打开工作台配方书并搜索九种设施/升级件；材料未齐时关闭可合成筛选，已有材料取出再放回也能解锁。
2. 按配方书制作打印核心、仓储箱、殖民地合成台和研究台，确认消耗与 [合成指南](survival-crafting.md) 一致。工作站的任意木板可混用，连接块每次产出八个；有限合成规则启用时，已解锁配方依然可制作。
3. 未研究时打印工人，配置台旁仓储，右键合成台或 O →“合成”，确认九种设施/升级件可选，石/铁/钻石工具仍锁定。下达设施、升级件和两次连接块配方，核对真实扣料、成品入仓、缺料/满仓等待及现有优先度。
4. 核对中英文物品提示、配方名称、二十二行配方的滚动/点击、小窗口与长名称布局。真实多人分别检查玩家所属工作站和库存，记录实际安装包 SHA256。

## 1.4.3 跨文件空值检查

`scripts/check-nullability.ps1` 必须先生成本轮主代码二进制，再逐个复查主文件，并分别编译 JUnit 和 GameTest 源集。此次用二进制依赖复现了 24 项测试警告，以及合并源码时没有出现的任务 enum 类型读取警告；只有旧版 95 文件合并检查成功不能证明这些诊断已解决。

## 1.4.4 合成库存提示修复

`CraftingService.Bank` 的三个预约快照使用 `activeClaims` 名称，预约数量读取通过非空校验后自动拆箱，分别对应字段遮蔽和可能为空的拆箱提示。避免额外调用 `intValue()`，否则会产生不必要拆箱的编辑器提示。预约不存在时数量为零，当前预约不包含的来源仍被拒绝，可用量继续扣除其他工人的预约。

运行跨文件空值检查、常规构建及服务端 GameTest，核对缺料恢复、已有材料预约、库存缩减、双端口去重、满仓等待和实际扣料。用户提供的提示来自编辑器提示提供者，ECJ 零警告和服务端通过须与实际编辑器列表刷新结果分别记录。

## 1.5.0 相似选择与上限设置

4. 弹窗内键盘输入、鼠标、右/中键和滚轮均不改变镜头或世界；关闭弹窗的点击不穿透。F6 可以退出。GUI 缩放与极小窗口仍不越界，可用 Esc 取消。

6. V 立体模式在六个面拖底面、松开鼠标选高度、再次点击确认；正负厚度、半格起始面、内部不同类型块均保持原行为。滚轮只缩放，镜头平移/旋转不计入选高。

## 1.5.1 右键清空与工人导航

1. 相似与立体模式分别建立选区，在场景右键单击，松开清空并取消未完成选择；追加开启时同样清空。Delete/工具栏仍可使用。
2. 按右键移动不足 4 个物理像素不平移，达到阈值开始平移；拖出后又回到起点再松开也不能清空。检查不同 GUI 缩放、窗口失焦及松开位置在 UI 上的情况。
3. 工作/预设/帮助/上限面板中的右键不影响世界选区；投影草稿的右键只用于镜头拖动，不清空选区。立体选高时右键单击取消、右键拖动保留选高。
4. 多工人同时施工、取工具、挖掘、清扫和合成，在行走途中触发材料扫描或站位重排，确认执行路线不被可达性探查改向；台阶、墙、转弯、不可达点和临时障碍需实际地形回归。路径阻塞后不得传送或强制加载区块。
5. 两名以上工人清扫最后一批物品，一名空手、一名仍持料时，任务应等待持料入仓后才完成。满仓/断连时持料不丢失，恢复容量或连通后继续；旧版已标记完成的任务重新下达一次清扫。
6. 自动场景覆盖活动路线与目标不受反复探查影响、执行路线提交使用正确目标、浮水设置同步及多工人持料完成条件；这些服务端测试不代替上述右键和真实地形游戏验收。

## 1.5.2 流水中的工人

1. 打开旧测试世界，给已有工人下达挖掘。在有坚实地面的单格深流水渠内，让工人从下游向上游行走；不应停在下游或不停跳浮，干地行走速度不变。
2. 挖开挡水方块，让水流进入工作面，再挖浅水中的石头/矿石。工人应使用水中站位接近目标、到位站稳，保持正确掉落、工具耐久和经验。
3. 工人应能爬出水渠的一格台阶；再检查转弯、宽水面、坡道、临时堵路。记录瀑布竖流与深水情况；本版未实现潜泳施工路线，不给深水、熔岩或无地面位置分配挖掘站位。
4. 暂停或取消工作后恢复普通水流推动，持料和工具不能丢失。打印核心仍要求干地；水下核心周围不能生成在水里的工人。
5. 服务端自动测试验证真实流体和实体运动；实际游戏动画、多人同步、复杂地形及性能需另行验收。最终记录见 validation/1.5.2.md。
