# 可复制的 UI 任务提示词

将下面整段交给接手的 AI，并提供仓库及 [交接说明](ui-handoff.md)。只有文件聊天权限时，至少一并提供说明里列出的 HUD/屏幕源码和语言文件；缺少工程时先交付布局方案与变更清单，不编造已完成的代码或测试结果。

```text
你接手的是 Minecraft 1.20.1 / Forge 47.4.0 / Java 17 模组 colonycamera 的客户端 UI。
当前参考版本为 1.6.1。请先检查真实工作区的 Git 状态，读 AGENTS.md 和
docs/ui/ui-handoff.md；以现有代码为准，保留已有改动和游戏存档。

核心体验：玩家亲手搭建自定义预设，再用战略视角规划殖民地，由工人施工。
本轮目标是紧凑、易找功能、少遮挡的战略 UI。直接给出可用的布局与客户端
实现，不讨论或重写 NPC AI、资源算法和施工系统。

用户已确定：
1. 底栏删除单选、相似、立体、追加、清空五个按钮。
2. 左侧“投影”点开二级菜单，含保存投影、放置投影、建造目录。
3. 最右侧“殖民地”点开二级菜单和概况，保留人物、科研等入口。
4. 殖民地旁常驻“挖掘”“清扫”，对已确认选区直接下单。
5. 中键单击循环“单选→相似→立体→追加”，追加沿用上次单选/相似工具。
6. 中键拖动保留解锁后的旋转；右键单击清空，拖动平移。
7. 空闲说明和空选区不常驻，建造目录保持窄侧栏、搜索/分类/收藏。

先画一个简短结构草图并列出修改文件，然后完成以下小批次：
A. StrategyHudLayout + StrategyHud：左右两组底栏，中央留空；投影/殖民地
   菜单互斥展开；悬停、激活、禁用、概况和短暂反馈可区分。
B. StrategyScreen + 现有面板：连接动作；任务、合成、科研打开指定页；
   人物只显示真实快照已有的 UUID 标识、挖掘等级、经验和工具。
C. 输入集成：中键在松开时判定短按，拖动阈值建议为 4 个物理像素；
   一旦越过阈值即永久视为本次拖动，不能回到起点后误切换。
   锁角度时的中键拖动不旋转也不切换，工具切换保留已提交选区。
   如只被分配 A/B，明确交出 C 的集成事项，不宣称完整需求已完成。

代码结构：
- StrategyHudLayout：纯 Java 的布局和命中矩形。
- StrategyHud：绘制，持有互斥菜单展开状态。
- StrategyScreen：输入优先级、面板生命周期和动作路由。
- WorkPanel / WorkPanelLayout：已有任务、合成、科技三页，人物页待补。
- ProjectionPanel：已有保存、预设库、本地投影和工程页。
- BuildPanel / BuildPanelLayout：已有窄建造目录和草稿条。
- ColonyWorkClient / ConstructionClient：只读快照和既有客户端意图。
- SelectionState / BlockSelectionController：已有三种选择算法及独立追加标志。

复用真实入口，不猜 API：
- ProjectionPanel.saveDialog()、library()；指定库页面/工程页的入口尚需补。
- StrategyScreen.openBuilding()。
- ColonyWorkClient.mine()、sweep()、refresh()、workers()、jobs()、tech()。
- ConstructionClient.refresh()、projects()、workers()、cores()、print(project)。
- WorkPanel 当前 open() 和 openStation()，没有公开 open(Tab) 或人物页。
详细的可用数据、方法权限、建议动作与循环状态见交接说明。

约束：
- 使用原生 Screen / GuiGraphics，所有布局按 GUI 像素，绘制与命中共用矩形。
- UI 优先处理输入；隐藏面板不拦截，点击菜单不能选方块/放投影/拖镜头。
- 打开完整面板时收起菜单并清理旧手势；保留 Esc/F6、失焦和缩放清理。
- 立体高度阶段跨 UI、镜头拖动须重设鼠标基准，不能重新锁回 UI 光标。
- 320×180 起的 GUI 可用；低高度菜单可滚动，不能越界或生成负尺寸。
- 建造已有绿色、可合成蓝色、无法获取红色，查询中单独表示。
- 中文文字可读，新增文字放 zh_cn.json/en_us.json，翻译键保持一致。
- 概况只说当前已加载数据，不能虚构全世界人数、资源总账或未提供的属性。
- 不改服务端 AI、扣料、配方、预约、优先度/FIFO、网络协议或存档格式。
- 不加 UI 框架、依赖模组、浏览器界面或空占位类；不关闭空值检查。
- 不碰 run/saves、配置、旧发布文件；不自动安装、推送或发布。

完成后维护相关布局/状态测试，运行 scripts/build.ps1，按 AGENTS.md 检查
空值契约和最终资源。UI、鼠标和进游戏的验证另列，不能把编译/纯 Java
测试说成实机成功。

交付格式：
1. 简短布局说明和实际修改文件。
2. 每个主入口/菜单项连接的现有动作，明确遗漏的集成项。
3. 已执行测试及结果；未验证的鼠标/游戏项。
4. 设计预览或游戏截图，明确其来源和性质。
```

若希望快速模型先只做外观，把以下限制附加到提示词最后：

```text
本次仅完成 A 的布局、绘制和纯 Java 命中测试。不要修改选择状态、镜头手势
和服务端。允许扩展实际使用的 HUD 菜单动作；如影响屏幕编译，完成必要的
路由接线或交出独立可审查补丁，不以空方法假装动作已实现。将 B/C 的真实
方法需求和后续接线清单交给集成者。
```
