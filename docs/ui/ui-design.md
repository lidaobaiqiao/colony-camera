# 战略界面设计方案（方案一 · 双端锚定）

日期：2026-10-06。设计基线：1.6.1 / `b8d894e`。**界面已于 1.7.0 落地，客户端实机待验收**；当前代码入口与差异见 [落地说明](implementation.md)。
原可交互预览为历史设计稿（含玩法占位数据），见 [`preview/index.html`](preview/index.html)（纯黑底，只画 UI，双击即可打开）。

## 一、总体形态

底栏拆成左右两组贴住屏幕两侧，**中央完全留空**供场景操作。

```text
┌──────────────────────────────────────┐
│ [选区摘要]                    锁 ? 退出 │
│                                        │
│              场景净空                   │
│                                        │
│ [建造][投影▴]      [挖掘][清扫][殖民地▴] │
└──────────────────────────────────────┘
```

中央净空按视口实测（左组 87px、右组 132px）：

| 视口 | 左组 | 右组 | 中央净空 |
| --- | --- | --- | --- |
| 320×180 | 87px | 132px | 85px（27%） |
| 640×360 | 87px | 132px | 405px（63%） |
| 960×540 | 87px | 132px | 725px（76%） |
| 1280×720 | 87px | 132px | 1045px（82%） |

旧底栏是居中 400px 实心长条，中央净空为 0。这是本次改动的核心收益。

## 二、几何规则

全部按缩放后 GUI 像素计算。`margin = min(8, min(W,H)/8)`，底栏高沿用 28。

按钮宽按 MC 字体度量计算——**CJK 步进 9px、ASCII 6px**，不用固定值：

| 按钮 | 宽度 | 计算 |
| --- | --- | --- |
| 建造 | 32 | 文字 18 + 内边距 12，取下限 32 |
| 投影 ▴ | 43 | 文字 18 + 箭头 13 + 内边距 12 |
| 挖掘 / 清扫 | 各 32 | 同建造 |
| 殖民地 ▴ | 52 | 文字 27 + 箭头 13 + 内边距 12 |

左组 = 建造 + 间隔 4 + 投影 + 内边距 8 = 87px。
菜单向上展开并贴住所属一侧，投影菜单左对齐左组、殖民地菜单右对齐右组，因此永不越出视口。

**文字必须按字体度量核算，不能凭视觉判断。** 现有 `StrategyHud.drawFitted` 已按 `font.width` 截断加 `…`，布局阶段需用同样的 9px 规则预判。

## 四、面板通用规则

以下四条是本轮修复确认的，写入规范：

1. **概况头高度按行数算。** 殖民地菜单三行文字占 0–28，分隔线须落在 29 之后，头高取 32。原先取 24 时分隔线压住第三行。
2. **进度条宽度必须夹取。** `clamp(round(track * done / total), 0, track)`。曾出现 412/400 = 103% 导致条宽溢出轨道。
3. **面板高度由内容驱动。** 固定高度在小内容页必然留白。任务 209 / 合成 213 / 科研 175 / 人物 207 / 工程 169。
4. **行高与步进成对约束。** 需满足 `步进 − 3 ≥ 行高`（3 为背景上移量），否则下一行背景会盖住上一行末行。任务行取行高 24、步进 27。

所有列表文字用统一辅助函数约束右边界，超出截断加省略号；CSS 另加 `overflow:hidden + text-overflow:ellipsis` 兜底。

## 五、建造目录

规格对齐现有 `BuildPanelLayout`，非重新设计：

- 面板 `min(248, 可用宽×2/5)` × `min(420, 可用高−32)`，窄视口下限 120×110
- 格子行高 26px，列数随宽度自适应
- 分类 7 项：全部 / 收藏 / 殖民地 / 自然 / 建材 / 机关 / 装饰
- 文案取自 `zh_cn.json`：标题「殖民地建造」、搜索占位「搜索名称、ID 或模组名…」、另有「可建」「刷新」
- 绿/蓝/红分别表示已有、可合成、无法获取；查询中单独表示
- **常驻面板**：点空白不关闭，只能点 `×` 或再次点击「建造」按钮
- 打开时「建造」按钮高亮，快捷键 `6` 为切换

分类排布随可用宽度切换：

| 视口 | 每格宽 | 排布 |
| --- | --- | --- |
| ≥640 | ≥32px | 横排一整行 7 项 |
| <640 | <31px | 折叠为单个下拉 |

下拉为**浮层**，覆盖在网格之上，不推移网格位置（与 `BuildPanel.categoriesOpen` 一致）。

网格容量：320→10 格、640→99 格、960/1280→143 格。

## 六、科研技术树

科研是**独立界面**，不是任务面板的页签。入口：科研页「开始研究」。

- 宽屏（≥520）左右分栏：宽438、高最多240，四节点树与详情并列
- 窄屏（<520）上下排列：树在上、详情在下；宽296、高最多240，最小支持视口夹到可用高度，详情可滚动
- 4 个现有工具科技阶段，四种状态：`done`（青点）/ `open`（金点，可研究）/ `lock`（灰点，不可点）/ `run`（研究中）
- 详情含前置、材料、耗时、解锁内容
- 依赖用 L 形连线表达，未完成前置的项缩进 8px

本轮按用户确认仅展示木器、石器、铁器、钻石四阶段；前置、材料、耗时从服务端读取。净水、耕种等 HTML 占位玩法不加入本版。锁定节点可查看详情，开始研究按钮禁用。

## 七、任务面板页签

五个页签统一渲染、全部可点：任务 / 合成 / 科研 / 人物 / 工程。宽度按 `tw(标签)+12` 计算，间距 3，总宽 172px。点击当前页不重复跳转。

原先是**两套死分支**：任务/合成/科研的页签无点击事件；人物/工程走另一套只画两个页签，其中「投影」按钮既无事件也不对应真实页面（工程数据在 `ProjectionPanel`，投影管理走 `P` 预设库的投影页），已移除。

## 八、历史落地前置条件（1.7.0 已处理）

以下几项必须先解决，否则 UI 接不上：

1. **`WorkPanel.Tab` 是私有枚举，且只有 `open()` / `openStation()`，没有 `open(Tab)`。** 必须补公开的任意页打开入口，五个页签才能互切。
2. **人物页需新增。** 现有快照 `Worker(id, miningLevel, xp, tool)` 无姓名、位置、饥饿、心情字段，界面不得推测填充。
3. **科研需独立数据包。** 现有 `Tech(tier, name, nextTier, costs, researchTicks, readOnly)` 只表达单阶段，**无法承载多节点依赖**。科研不应塞进 `WorkPanel` 的 Tab。
4. **概况头、进度条夹取、内容驱动高度、行高步长约束**四条规则需同步到 Java 绘制与布局。

## 九、多窗口历史评估（1.7.0 已实现）

建造窗口**多开、拖动、缩放**。源码核实结论：三项**在1.6.1中完全不支持**——

- `StrategyScreen` 为单实例 `private final BuildPanel building`，共 23 处 `building.*` 引用均假定单例
- `BuildPanelLayout.panel = new Rect(margin, margin, w, h)`，位置与尺寸写死
- 无任何 drag / resize / 多窗口相关字段

历史实现评估如下；本版由 BuildWindows、WindowGeometry、BlockDraftState 落实：

| 特性 | 难度 | 关键冲突 |
| --- | --- | --- |
| 拖动 | 中 | 标题栏拖拽需在 `blocksWorldPointer` 之前拦截；`clearPointerGesture()` 目前在 `mouseClicked` 开头无条件执行，会抢走手势 |
| 缩放 | 中 | 构造器需接受外部矩形；`columns` 已自适应，网格会自动跟随；尺寸须夹在视口内并持久化 |
| 多开 | 高 | `click/scroll/keyPressed/charTyped` 需改为遍历命中；`ProjectionController.startBlock()` 是**全局单状态**，同时开两个目录会互相覆盖选中方块，需加窗口级草稿缓存 |

已确认的决策：**每窗独立草稿**（而非共享当前方块），因为多开的意义是对比挑选，共享会让开两个窗口失去意义。窗口布局需持久化到客户端配置。

`BuildPanel` 现有 ADR 见 [0016-building-palette-and-supply.md](../decisions/0016-building-palette-and-supply.md)，
其中「类别是本模组的检索分组，不冒充原版创造栏分类」为既有边界；本次分类横排与下拉只对齐原版**操作习惯**，不改分类语义。
