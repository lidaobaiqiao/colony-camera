# 殖民地界面系统规划

日期：2026-10-14。状态：设计基线稿；2026-10-17 已落地 [1.13.0 首轮](implementation-1.13.0.md)，其余部分仍为提案。规划基线为 1.12.0 源码；2026-10-06 的 ui-design.md 与 0020 保留为历史设计记录。本文的尺寸、组件和流程是可调整的设计选择，不新增游戏规则。

## 1. 目标与现状

界面服务于「看清世界 → 规划 → 下达任务 → 理解执行结果」。世界是主要操作空间，面板按需展开。视觉方向是克制的殖民地工具界面：清楚的层次、原版方块/物品图标、小面积青色强调、方正轮廓；不采用覆盖世界的大块装饰、玻璃模糊或后台仪表盘布局。

源码核查发现：

| 现状 | 证据 | 影响 |
| --- | --- | --- |
| 双端底栏、中键短按切工具已经实现 | StrategyHudLayout、StrategyScreen、0020 | 保留这套肌肉记忆，问题重点在展开后的内容 |
| 人物面板居中，最多 400×320 | WorkerPanel.resize | 640×360 GUI 下占屏 55.6%；320×180 下为 304×164，占屏 86.6% |
| 工作面板宽最多 540，列表高度扣除 118 | WorkPanelLayout | 320×180 只剩约 46 高，最多显示一条 27 高任务；框能容纳不等于操作有效 |
| 合成面板最多 344×240，窄屏仍固定左右结构 | CraftingPanelLayout | 320×180 下为 308×168，占屏 89.8%，配方列表仅一行 |
| 人物六页主要由相同文字行生成 | WorkerPanel.Row / render | 状态、解释与操作视觉相似，18 项属性淹没当前问题 |
| 颜色和控件绘制分别散落于面板 | StrategyHud、WorkerPanel、StorageScreen 等 | 更新一个控件不能同步全局样式与状态 |
| 旧设计文档仍描述四节点科技和早期人物字段 | docs/ui/ui-design.md | 现在已有八节点科技、需求、关系、装备及住所配置，不能照旧稿扩展 |

本轮先交付设计与交互样例。样例采用虚构的演示快照，不连接游戏；它证明布局和点击流程，不能证明 Minecraft 字体、射线、网络回执或帧率。

## 2. 信息架构

```text
世界操作层
├─ 左下：建造 / 投影
│  ├─ 建造目录 → 方块详情 → 世界投影 → 工程回执
│  └─ 投影菜单：保存预设 / 预设库 / 已放置投影 / 选择设置
├─ 右下：挖掘 / 清扫 / 殖民地
│  ├─ 挖掘：选区摘要 → 优先度 → 提交
│  ├─ 清扫：顶面选区 / 当前批次物品类型
│  └─ 殖民地菜单：人物 / 住所 / 任务 / 合成 / 科技 / 仓储入口
├─ 左上：当前选择工具；有选区时增加数量/尺寸/筛选摘要
├─ 右上：角度锁定 / 帮助 / 退出；有重要问题时出现可展开提示
└─ 底部中央：仅在选高、放置等操作期间显示短提示与操作条

展开内容
├─ 检查器：人物、住所、工程/任务详情，右侧按需出现
├─ 工具面板：建造目录、预设库，左侧按需出现
├─ 管理窗口：任务列表、合成配方书、科技树，显式打开
└─ 对话框：命名、打印配置、装备选择、需要确认的破坏性操作
```

「任务」把施工工程和挖掘/清扫/生产/研究放在同一个视图，通过类型筛选区分；两类服务端模型与命令仍分别保留。原「工程」入口直接打开施工筛选，不增加重复窗口。「选择设置」收纳相似上限、立体方块筛选和追加状态，不再占用底栏。

殖民地菜单只显示少量实际摘要与功能入口，不能再塞一整页数据。没有告警时不常驻压力、温度、材料等大面板；必要的问题用数量和短标签表示，点开才能查看细节。

## 3. 世界空间与窗口规则

### 布局选择

以下单位均为 Minecraft 缩放后的 GUI 像素，不能拿显示器物理分辨率套用。屏幕边距 8；按钮/行高主要使用 18、22、26；8 为大分组间距，4 为同组间距。

| GUI 尺寸 | 默认表现 | 展开后的表现 |
| --- | --- | --- |
| ≥640×360 | 双端底栏；按需左工具、右检查器 | 检查器宽约 32%，限制在 196–248；高度不覆盖上下操作区。宽管理窗口显式打开 |
| 480×270 | 底栏保持文字；摘要压成一行 | 侧面板约 176；详情分组折叠。配方书/任务窗口在列表与详情之间切换 |
| 320×180 | 底栏仍保留五个必要入口，次要信息进菜单 | 简短检查器宽约 128–144、高约 108；复杂内容用有「返回」的独立管理页，不能把宽屏全内容缩小硬塞 |
| 更小/暂时极小 | 保留关闭/返回，暂停拖动与选高 | 明确尺寸不足，不提交当前手势；恢复尺寸后重新布局 |

推荐验收目标：默认 HUD 不遮住超过 20% 场景面积；640×360 打开一个侧面板时仍留至少 65% 世界净空。320×180 的复杂管理页允许更大占屏，但必须由玩家主动进入，退出后恢复规划现场。占屏按可交互矩形的并集计算，不能只算半透明像素。目标是待验证预算，不宣称当前已达到。

### 生命周期

- 普通菜单互斥；点击同一入口收起。点外部先关闭菜单并消费该次点击，不能顺手下达世界命令。
- 检查器跟随明确选中的工人、住所或任务；点击其「定位」只移动镜头，不能更改玩家位置或世界加载范围。相应定位数据缺失时显示原因。
- 常驻建造目录点世界不关闭；选中方块只生成本地草稿，工程须等服务端受理。关闭目录只取消本地放置态，不取消已受理工程。
- 保留最多八个独立建造窗口、每窗搜索/分类/收藏/草稿、拖动和缩放。默认只开一个；提供最小化与窗口切换条，鼓励把比较窗口收起，不削减八窗能力。只有活动草稿进入世界预览。
- 不同管理页默认复用一个管理窗口；切换页保留各页搜索、滚动和选中对象。装备选择等临时页返回原人物与页签。
- 关闭、切维度、退出世界、对象消失、区块卸载均有明确结果。未知状态不伪装成空闲；旧任务/草稿不因重新绘制而重建。
- 面板拖拽结束、缩放窗口或 GUI scale 变化后夹取边界，关闭按钮和至少一段标题始终可见。仅布局与明确的用户显示设置跨会话保存。

## 4. 视觉系统

推荐主题保留现有深色与青色，但降低大面积彩色背景，增强正文/次要信息差异。游戏内先实现一个稳定主题；亮色仅作为后续可选方案，不要求两套渲染。

| Token | 推荐深色值 | 用途 |
| --- | --- | --- |
| surface | #14212B | 不透明的内容面板，阻隔后方纹理 |
| raised | #1D303C | 悬停、输入框、可操作控件 |
| border | #344A57 | 一像素分隔与边界，不能每行都画框 |
| text | #E8F0F3 | 标题、关键状态、数值 |
| secondary | #B4C2C9 | 次要信息，仍需清晰可读 |
| accent | #67DEC2 | 当前工具、焦点、已选项目；不用作全屏背景 |
| success / craftable / blocked | #86D39A / #83BCF4 / #EAA19A | 已有 / 可合成 / 无法获取；配文字和符号 |
| mining / sweeping | #EBC96D / #83BCF4 | 世界挖掘标记 / 清扫顶面标记，保留既有语义 |

控件使用方角或小切角，不做大型圆角卡片。原版物品、方块和实体图标用于内容识别；自绘小图标只用于通用动作。按钮优先「图标 + 短文字」，不可只靠一个陌生图标。颜色表示当前状态，不把所有职业/页签任意染成不同颜色。

Minecraft 原字体按实际 Font.width/split 度量。一级标题、正文、次要文字主要靠间距/明度区分，不以任意缩小字体解决拥挤。数据右对齐并使用稳定列宽；坐标、UUID、完整名称放进详情，列表优先显示可辨识的短名称与状态。关键信息不得仅在悬停中出现。

按钮统一支持默认、悬停、焦点、按下、选中、禁用和请求中七态。选中使用小面积填色/下沿标识；禁用显示明确原因。请求中保留原按钮位置和尺寸，防止列表跳动及重复提交。全局动画只用于必要的短反馈，避免大量发光、模糊与循环动画；低动态设置关闭过渡。

## 5. 各界面规格

### 建造与预设

建造目录是窄工具，不是主窗口：搜索、分类、收藏、可用状态筛选、图标网格。宽屏分类可横排，窄屏合并为下拉。网格显示原生图标，状态通过边角标识表达：✓ 已有、◇ 可合成、! 无法获取、… 查询中。红色项目仍能查看原因，不静默隐藏。

选中项目后显示一段就近详情：名称、真实库存数量/所需数量、合成前置、阻塞原因。库存查询中、未确认与不可达不能当作零。蓝色说明「将自动合成后建造」，绿色情况只消耗实际可用成品。此分类不等于玩家背包内数量。

放置期间底部中央临时出现名称、旋转/镜像、高度、确认/取消；放置后显示「提交中 → 已创建工程」或服务端拒绝原因，不能用本地投影存在冒充施工成功。目录可以收为小条以增加视野，草稿位置不变。

预设库用有名称、尺寸、方块数、创建信息的缩略项目；搜索、收藏与列表/缩略图切换按需提供。无法生成真实缩略图时使用明确默认图，不伪造建筑图片。保存流程：选区检查 → 名称/摘要 → 保存结果；空选区入口解释缺少选择，而非弹空对话框。放置与已放置投影分开，后者链接实际工程状态。

### 挖掘、清扫与类型选择

挖掘点击后出现紧凑下单条：目标数量、优先度、确认/取消。没有选区时说明需要先选择。清扫点击后明确两种模式：选中方块顶部 / 按物品类型清扫当前可达批次；后者没有方块选区也能打开。类型选择有搜索、多选勾选、已选标签与清除筛选，确认后才改变规则。

立体选择以前设置筛选，完成后摘要显示「立体 · 128 块 · 石头等 2 类」。工具模式保持中键循环，追加沿用上次单选/相似，状态标签组合展示「相似 + 追加」。清空仍为右键，不增设常驻按钮。黄色任务轮廓与蓝色顶面属于已受理任务，不因右键清空鼠标选区而消失。

### 任务与工程

管理列表每条只显示：类型图标、名称/位置摘要、状态、完成比例、优先度。创建序号和细分材料进详情。可按类型、状态、优先度过滤；同一优先度仍遵守服务端 FIFO，UI 排序不改变派工。

选中后展示「正在做什么 / 为什么不能继续 / 怎么处理」。例如：「等待材料：橡木木板还缺 4 → 查看配方」；「无可达站位 → 定位目标」。必须显示服务端已知原因；若只收到泛化原因，保持概括，不猜工人路径。批量暂停、优先度与取消有明确选中数量；已完成/已取消的动作状态不同。失败不抹去原列表和滚动位置。

### 人物与打印

人物列表显示短标识、职业、当前工作/生活原因、最紧急问题。尚未支持自定义名字时用现有显示名或短 UUID，不宣称存在改名能力。

检查器头部只保留身份、状态及定位入口。内容分「概况 / 工作 / 装备 / 成长 / 生活 / 关系」：

- 概况：健康、饥饿、休息、压力；展开压力来源。忠诚展示真实数值，不画 0–100 饱和条，因为忠诚不是压力上限。
- 工作：五类任务开关、自动取工具、当前任务与持料归属；个人资格不冒充全局优先度。
- 装备：可见槽位、实际物品与耐久；选择来自玩家真实物品栏，提交结果明确，旧装备回收失败原因可见。主手运输材料不当成可换装备槽。
- 成长：18 项属性按基础/职业分组，默认折叠次要项；点数、独立效果和进度分别标注。学习入口链接真实学堂/课程条件。
- 生活：实际住所、饮水、温度、社交需求、食物品质及可用设施；单位和范围明确，不把所有数值统一归一成百分比。
- 关系：真实对象、已加载状态、亲近度和相处时间；「未加载」不能写成死亡。忠诚与人际关系分开，未实现的恋爱/争吵/艺术事件不展示可用按钮。

既有特殊指令置于折叠的「高级指令」区域；危险命令显示对象、条件和影响，二次确认只能提交已明确的玩家意图。打印单独打开配置对话框：核心、兴趣/性格及真实门槛，醒目写明「无需住所」。不存在对应后端行为的拟议功能标为后续，不能放活按钮。

### 住所

检查器呈现房间名称/位置、合规状态、面积、床、住户、自动入住开关。不合规时直接列出实际原因，配置不能把不合规房间改成合规。修改住户预览变更对象，保存后等回执；跨属、已入住另一处和无法解除原认领应保留原配置并解释。布局和摘要不引入额外住房需求。

### 合成与仓储

合成保留原版配方书习惯：默认全部配方、名称/ID/模组搜索、分类、原版产物图标、3×3 材料配方与产物数、批量数、工作台选择。未解锁、缺料、无法自动生产分别显示原因；灰色不能兼指「尚未查询」。宽屏列表和详情并列，窄屏点配方进入详情并可返回，搜索和页码保留。下单后显示真实队列状态，不立刻增加库存。

仓储菜单保留原生槽位交互与玩家背包；大堆叠实际数量单独标注，不能混淆槽内展示栈。网络容量与连接状态就近显示。跨仓储资源总览若新增，必须标注统计范围、加载状态、预约占用和网络去重；目前缺统一可达资源快照，不把示例数据当成实现完成的总览。

### 科技

当前仅八节点：木制基线、石/铁/钻石工具、集中供水、住所保温、社区生活、公共教育。工具与生活分栏，真实前置画连线；供水的实践条件不伪造为必须先完成某工具科技。锁定节点允许查看详情。

节点显示名字与「完成 / 可研究 / 条件未满足 / 研究中」，真正进度只出现在正在研究节点。详情按「能力 → 前置实践 → 材料 → 工作站与有效时间 → 操作」排列。研究按钮禁用原因就在旁边；没有科学点的系统不能画研究点计量。窄屏采用节点列表/分支切换与详情页，而不是缩小整棵树。

## 6. 输入与反馈契约

| 输入 | 世界 | 面板/弹层 |
| --- | --- | --- |
| 左键 | 当前选择或放置操作 | 顶层控件优先，提交失败不透传 |
| 右键短按 | 清空已有选择；活动草稿优先取消/退出本地放置 | 仅执行面板明确的功能，如建造格收藏；绝不清空后方世界 |
| 右键拖动 | 保留现有镜头平移 | 面板内不启动镜头手势 |
| 中键短按/拖动 | 切选择工具 / 解锁时旋转 | 被 UI 消费，不能触发工具切换或镜头 |
| 滚轮 | 镜头缩放，不能改变选高 | 鼠标下最近的可滚动内容优先；到边界也不传给世界 |
| Esc | 先取消当前未完成手势/草稿，最后退出 SLG | 顶层对话框 → 二级菜单 → 当前详情/窗口；一步只关闭一层 |
| 输入字段中的按键 | 不启动世界操作 | 搜索/命名字段独占文本输入，离开字段清除被挂起的手势 |

Esc 的最终顺序由一个焦点栈表达，避免现在每个面板分别决定关闭顺序。不是给全世界加透明挡板：非模态面板只消费实际区域和捕获手势；真正模态页消费整屏。菜单外的首次关闭点击按前述规则消费。绘制层级与命中层级保持一致。

瞬时成功提示 2–4 秒；真正阻塞提示保留至状态变化/用户处理。空列表解释「未创建」「筛选无结果」「尚未加载」三种原因。数据请求有查询中/超时/过期/只读状态；数量未知使用「—」，不显示 0。按钮请求中禁止重复提交，回执绑定原对象 UUID，后台更新不能把结果落到另一窗口。

## 7. 数据、组件与实现路径

### 复用边界

| 界面数据 | 现有来源 | 需要补充的边界 |
| --- | --- | --- |
| 工人属性/生活/压力/关系/装备/任务偏好 | WorkerSnapshots、ColonyWorkClient | 统一显示模型；定位坐标与显示名需确认快照，不从 UUID 推测 |
| 科技节点/材料/进度/实践原因 | TechProgress.describe | UI 消费节点，不维护客户端科技树真值 |
| 工程/附加任务/优先度/阻塞原因 | ConstructionClient、ColonyWorkClient | 统一列表只读适配，保留各命令归属 |
| 建造可用/可合成/不可获取 | BuildingClient、服务端目录预演 | 查询中与失败单独处理，保留动态数量与预约 |
| 住所检查/住户/配置 | WorkerSnapshots、ResidenceOrders | 编辑草稿与真实快照分离 |
| 仓储数量/连接/容量 | StorageMenu 与设施状态 | 统一全殖民地可达资源/定位快照尚需后端设计 |

建议先从真实重复处提取 UiTheme（颜色/间距）、UiDraw（文字、按钮、图标、进度）、UiFocus（顶层输入/捕获）、ScrollList（裁剪/滚动/空状态）；只在使用时创建，不先搭庞大组件框架。复杂布局仍保持纯 Java，渲染与命中共享 Rect。人物页的分组显示模型与网络实体解耦，不能把服务端逻辑放进控件。

### 迭代顺序与完成条件

1. **基础视觉与输入**：统一 token、控件七态、焦点/关闭路径；保留现有底栏和快捷键。完成条件：界面外规划可用，界面内无穿透。
2. **高频规划**：建造目录、投影、选择设置、挖掘/清扫下单条。完成条件：连续建造无需反复重开，三种材料状态可读且受理回执明确。
3. **执行可解释**：统一任务视图、人物和住所检查器。完成条件：从问题找到对象、定位、处理、返回不丢现场。
4. **管理**：合成配方书、八节点科研、原生仓储菜单。完成条件：窄屏仍可查全部配方/节点，不能只看到一行而找不到详情。
5. **游戏验收**：真实 MC 中文/英文、不同 GUI scale、鼠标重绑定、切维度、多人回执和长期运行。布局检查与交互样例不能替代这一阶段。

每步单独可交付，不把整套 UI 大改与工人 AI/存档重构绑在一起。需要新增服务端字段时单列版本/协议变化，本次规划不改版本、协议、存档、发布包，并保留已有 README 变更。

## 8. 验收清单

- 320×180、400×225、480×270、640×360、960×540，中文/英文及长名称：必需按钮和数字可见，文本按真实字体折行，关闭/返回无需悬停。
- 默认底栏、一个检查器、两侧面板、多建造窗口、管理窗口、命名/装备弹层逐种测占屏与遮挡；开放世界区的输入行为符合当前状态。
- 世界高差、背后方块、放置草稿与已受理投影同时出现时，UI 不影响射线判断；进入/离开面板重设选高基准，不改变层数。
- 鼠标 UI 内按下/世界松开、世界按下/UI 松开、拖动后返回起点、失焦、调 GUI scale：不会误提交、切工具或卡住光标。
- 全部配方/科技可查；绿/蓝/红/灰查询态不用颜色作为唯一信息。无选区清扫仍能选择物品批次。
- 工人满压力、低忠诚、无住房、无水、不可达、对象卸载、未知只读：显示实际原因，不把配置/画面制造成状态改善。
- 任务暂停/取消/抢占、库存变化、满仓、回执延迟、重复点击、后台窗口回执：真实物品、进度与用户草稿不丢失。
- 输入字段中文输入法、Tab/焦点、Esc 返回、快捷键冲突；屏幕朗读或无色视觉模式有明确文字/符号。
- 对大列表仅渲染可见行，缓存图标索引和静态布局；不在 render 中扫描世界、请求路径或重复发包。帧率/TPS 以实机测量记录。

交互样例的行为验证另记；计划本身不宣称任何 Java 界面已改好。下一步按第 1、2 阶段先落地，再用真实游戏反馈调整密度。
